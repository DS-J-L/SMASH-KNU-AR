## 아직 확정하지 않은 설정

- 휴대폰 기종·OS·브라우저, PC 사양과 연결망
- MediaPipe 모델·해상도·추론 주기와 GPU 사용 가능 여부
- 폰 촬영 시각의 정확한 출처와 공통 시계 변환 방법
- C0 실시간 영상 전송 방식과 보정 영상의 일치 방법
- 보정 기준물 크기·마커 사전·각 면의 좌표
- 허용 시간차·프레임 수명·재투영 오차·타격 속도·cooldown (서버는 `config/project*.json`에서 읽음. `max_frame_age_ms`가 null이면 서버 기본값 250ms, 늦은 카메라 대기 `max_wait_ms` 제안값 100ms)
- 3D 정렬에 허용할 촬영 시각 출처(기본 `capture_metadata`만). 실제 폰 브라우저가 촬영 메타데이터를 주는지 확인 필요
- 게임 세션 ID의 생성 주체(현재 `pose_3d.session_id`는 서버 실행 단위 ID)
- PCK의 2D/3D 구분, 정답 좌표 작성법·허용 오차·정규화 기준
- 6명 평가 또는 12명 비교 평가의 최종 선택, 과제 순서·휴식

`config/*.example.json`의 숫자는 초기 제안이며 달성 성능이 아닙니다. 보정 행렬은 실제 측정 전까지 채우지 않습니다.

### 2026-10-30 — D07 근거 범위 정정

외부 에이전트 산출물에는 세부 방식을 “팀 결정”으로, ipTIME CAA 실패·DuckDNS 발급 진행을 담당자 보고로 기록했다. 이는 산출물에서 가져온 과거 기록이며 이번 세션에서는 독립 확인하지 않았다. 현재 대화로 확인된 것은 로컬 PC + ipTIME 포트포워딩 방향과 산출물 반영 요청이다. DuckDNS·win-acme·8443 선택, 인증서 발급 결과와 외부/휴대폰 접속은 검증 대기로 관리한다. Caddy는 대화에서 제안했으나 이번 반영에 추가하지 않았다.
