## 2026-11-16 마커 자동 인식

폰 카메라를 켜고 고정 단계에서 마커 검은 사각형의 실제 한 변과 바닥~렌즈 높이를 확인한 뒤 **마커 자동 인식**을 누른다. 기존 assets/markers/floor-direction-id0의 ArUco DICT_4X4_50 ID0 인쇄물을 사용한다. 입장용 QR이나 단순 흑백 사각형은 대상이 아니다. 흰 여백과 검은 테두리 전체가 영상 안에 보여야 한다.

검출은 최대720px 프레임에서 명암 분리→연결성분→볼록 외곽/사각형→검은 테두리와 ID0 비트·방향 검증을 수행한다. 같은 ID0가 여러 개면 거부한다. 6회 이상·900ms 이상 연속 안정 후 모서리를 확정하고 기존 화각/높이·자세 보정 품질검사를 적용한다. 초록 테두리와 보정 결과를 확인한 뒤 몸 보정으로 진행한다. 1대 자동 경로도 인쇄 마커 방향을 쓰고 저장된 모서리 방향을 보존한다. 검출·보정이 실패하면 거리/각도/반사/인쇄 크기를 확인하거나 **수동으로 모서리 찍기**를 쓴다.

자동은 모서리 선택을 대체하며 실제 마커 크기·카메라 높이 측정이나 렌즈 실측을 대체하지 않는다. 확정 후 검출을 중단하므로 마커/사람 움직임에 건물이 따라 움직이지 않는다. 카메라를 옮기면 마커와 몸 보정을 다시 한다. 합성 영상에서 1대/3대 경로와 회전/원근/잡음/오인식 거부를 검증했으며 실폰의 최대거리·역광/반사·추가부하는 미검증이다.



## 2026-11-16 현재 기준 — 최초 허리 고정

- 1대는 기존 마커 위 직립 몸 보정 완료 때 허리 기준을 한 번 만든다. 허리는 기존 키×0.6 추정(0.6~1.3m 제한)이며 실측 센서가 아니다. IT1 단독 높이를 이 값으로 정하고 바닥 마커 (0,0)에 고정한다. 이후 움직임/앉기/키 추정 변화/복원으로 자동 크기·위치를 바꾸지 않는다. 명시적으로 몸 보정을 다시 하면 새 기준을 만든다.
- 구역은 2개를 앞에, 가장 높은 1개를 뒤에 놓고 전체 바닥 외곽의 중심을 마커에 맞춘다. 2개 구역은 좌우 중앙 배치다. 기존 87개 평균높이0.95m로 정한 공통 축척에 최초 허리/0.95를 한 번 반영한다. 구역 전환은 동일 보정 비율을 사용하므로 같은 건물의 크기는 바뀌지 않는다. 모든 건물 높이가 각각 허리와 같다는 뜻은 아니다. 기존 고정0.95m/가로 일렬 배치 설명은 이전 정책이다.
- 3대 폰은 각자 마커 보정→몸 보정 화면으로 진행한다. 세 폰을 모두 연결한 뒤 한 폰 또는 PC 건물 시험의 '세 폰 몸 보정 시작'을 누른다. 마커 위 직립/양발접지, 코·어깨·골반·발목의 유효 3D와 세 시점, 최소20표본/2.5초 이상 연속 안정성을 확인해 허리를 저장한다. 완료 전에는 새 폰의 실제 손 타격을 중단한다. 재연결/카메라 재보정은 재몸보정을 요구하며 옛 크기를 실시간으로 추종시키지 않는다. 타임스탬프가 없는 구형 합성/재생 테스트 메시지는 호환 경로이며 실기기 완료 근거가 아니다.
- 폰 페이지는 건물과 충돌체를 그리지 않는다. 건물·충돌체·파편은 PC 화면에만 표시한다.
- 측정/몸보정 화면은 전체 원본 프레임을 contain으로 표시해 화면 잘림을 막는다. 전체 건물 외곽이 영상 여백6% 안에 들어오는지 검사하고 부족하면 거리/각도 변경·마커/몸 재보정 안내를 표시한다. 고정된 실제 크기를 유지하므로 가까운 카메라에서 임의로 세 건물을 모두 보장하거나 매 프레임 축소하지 않는다. 넓은 건물 구역은 상당한 촬영 거리가 필요할 수 있다.
- 배포는 npm run build:building-test 후 서버 재시작·폰/PC 새로고침. 실폰 허리/정합 정확도·시야 확보·장시간은 미검증이다.


`/test/mono3d/`는 **시험용 정적 페이지**다. 폰 카메라 1대와 바닥 ArUco 마커(검은 정사각형 20cm)로 카메라 자세를 구하고, MediaPipe Pose로 손목의 3D 위치를 **추정**한다. 방·게임 코드와 연결하지 않는다. 측정 단계에서는 결과와 영상을 시험용 중계 경로로 PC 화면에 보낸다(아래 "PC 화면으로 보기", 끌 수 있음). 결과는 `source: mono_approx`로 표시하며 다중 시점 3D(P3) 완료 근거로 쓰지 않는다.

## 계산 방식

PC 건물 시험은 3대 `/test/building/`에서 ‘시험 구역’을 선택해 캠퍼스 8개 대구역의23개 소구역(1대 `?mode=mono`는 한 번에 건물 하나만 세우며 ‘건물 선택’ 목록에서 고른다)(건물2~3개,총61개)을 표시한다. 고정높이0.5m 미만26개는 목록에서 제외한다. 최초87개 평균 높이0.95m로 정한 절대 축척은 유지하며 필터링/몸보정/구역 전환으로 크기를 바꾸지 않는다. 기존 폰 전송·보정 절차를 그대로 쓴다. 크기·충돌·성능 한계는 [건물 파편 시험 안내](BUILDING_FRAGMENT_TEST.md)를 따른다.

2026-11-11 보정 품질 보완: 마커가 작거나 납작하게 보이면 모서리 오차가 작아도 바닥 수직 방향은 크게 틀릴 수 있다. 원본 영상 짧은 변 720px 기준 유효 마커 폭 24px 미만, 재투영 최대 오차 3px 초과, 각 모서리 좌표를 ±1px 움직였을 때 수직 방향 변화 15° 초과는 보정을 거부한다. 해상도에 비례해 픽셀 기준을 조정한다. 실패 시 폰을 더 가까이 또는 위로 옮겨 마커를 크게 찍는다. 저장된 보정도 재사용 시 같은 검사를 거친다. 기준은 합성 사례 기반의 초기값이며 실측 정확도 보장은 아니다. 이 변경은 건물 높이 자동 설정과 별개다.

1. **마커 보정:** 사용자가 마커 네 모서리를 먼 왼쪽 → 먼 오른쪽 → 가까운 오른쪽 → 가까운 왼쪽 순서로 누른다. 화각(대각)으로 만든 근사 K와 호모그래피로 초기 자세를 구한 뒤 재투영 오차를 최소화해 다듬는다. 원점은 마커 중심이고 +X는 오른쪽, +Y는 카메라에서 먼 쪽, +Z는 위다(`room_z_up`, m). 폰 높이를 알면 그 높이가 나오는 화각을 역산할 수 있다. 다만 마커 하나로 역산하면 민감하므로, 렌즈 보정값이 생기면 그 값을 쓴다.
2. **몸 보정(3초):** 두 발 사이 중심을 마커 중심에 맞추고 양발을 바닥에 붙여 똑바로 선다. 머리/몸통/양발목이 보여야 하며 기존 바닥 추정의 발목 중심이 마커에서15cm를 넘으면 보정을 거부한다. 마커 중심을 지나는 카메라 쪽 수직면과 발목/코 픽셀광선의 교점으로 발목 높이·몸 배율을 구한다. 실제 키를 입력하면 그 키를 우선 사용한다(코 높이 ≈ 0.92 × 키로 근사). 몸을 기울이거나 한 발을 들면 거부한다. 최종 표본의70% 이상이 유효해야 하고 위치 흔들림8cm·배율 편차15%를 넘으면 다시 보정한다. 이 기준들은 합성 시험의 초기값이다.
3. **매 프레임:**
   - 보정된 발목 높이 평면과 보이는 발목 픽셀광선의 교점을 구한다. 모델 기준으로 낮은 발을 쓰고, 양발이 같은 높이면 평균을 기준점으로 삼는다. 보정 중 관측한 바닥 중심 편차를 보정한다. 원점은 계속 마커이며 측정 중 사람은 자유롭게 이동한다.
   - 나머지 관절은 worldLandmarks에 배율을 곱해 기준점 주위에 놓는다.
   - 각 관절을 자기 2D 픽셀 광선 위로 옮긴다. 그래서 좌우·상하 위치는 2D 검출을 따르고, 깊이만 몸 모델에서 온다.
   - 새 마커 기준 보정에서는 발목이 둘 다 안 보이면 `feet_required_for_depth`로 좌표를 무효화하고 타격을 멈춘다. 몸통 크기만으로 깊이를 대신 추정하지 않는다. 과거 보정 형식의 수학 API는 이전 시험 호환용으로 남기지만 현재 폰 화면은 항상 새 보정을 쓴다.
4. **건물(타격 대상):** 마커 자리 바닥 위에 세운 기둥이다. 기본 폭·깊이 0.3m, 높이는 허리 높이(키 × 0.6, 0.6~1.3m로 제한)다. 키를 입력하면 그 키, 없으면 몸 보정의 추정 키, 둘 다 없으면 0.95m를 쓴다. 손목이 건물(여유 포함) 안으로 들어오는 순간, 또는 직전 프레임에서 현재 프레임까지의 이동 선분이 건물을 지나가는 순간을 타격 1회로 센다. 프레임 간격이 250ms를 넘거나 1.5m 넘게 튀면 선분 판정은 쓰지 않는다.

   보정이 끝나면 마커를 치워도 된다. 마커가 있던 자리가 좌표 원점으로 남는다. 단, 폰·줌·해상도·화면 방향이 그대로여야 하고, 폰이 움직이면 마커를 같은 자리에 다시 놓고 마커 보정을 다시 한다.
5. **기록:** 매 프레임 결과를 JSON으로 내려받는다. 보정값·몸 배율·건물 설정이 함께 저장된다.

## 실행

서버 실행은 기존과 같다. 폰에서 `https://<PC 주소>:8443/test/mono3d/?key=<접속키>`를 연다. 이 페이지는 공개 경로가 아니라서 접속 키가 필요하다.

화면은 카메라가 전체 배경을 채우고, 아래 안내 카드가 단계를 따라간다(PC에서는 오른쪽 카드).

1. **카메라:** 후면 또는 전면을 고른다. 전면은 화면만 거울처럼 뒤집고 계산은 원본 영상으로 한다. 보정은 카메라 방향별로 따로 저장된다.
2. **고정:** 폰을 고정하고 높이·마커 크기를 확인한다. 같은 자리라면 저장된 보정을 바로 쓸 수 있다.
3. **모서리:** 화면이 멈추고 영상 전체가 보이게 바뀐다. 안내 그림을 따라 네 모서리를 누르고, 결과의 초록 사각형이 마커와 겹치는지 확인한다.
4. **몸 보정:** 시작 후 카운트다운(3/5/10초) 동안 두 발 사이 중심을 마커 중심에 맞춘다. 화면의 초록 수직선/준비 상태를 보고 양발을 바닥에 붙여 몸을 세운다. 큰 숫자와 삐 소리로 안내하고 그 뒤3초간 측정한다. 성공 결과의 마커 기준/발목 높이를 확인한다. 키를 바꾸면 몸 보정을 다시 한다.
5. **측정:** 손목 좌표·위에서 본 지도·건물 타격 횟수를 보여 주고, 기록을 JSON으로 내려받는다.

화각·좌우 반전·건물 크기와 위치·저장된 보정 지우기는 ⚙ 설정에 있다. 화면을 채우면 많이 잘리는 경우(예: 가로 화면에 세로 영상)에는 전체가 보이게 표시한다. 폰 방향·해상도가 바뀌면 경고하고 계산을 멈춘다. 측정 중에는 화면이 꺼지지 않게 요청한다(지원 브라우저만).

## PC 화면으로 보기 (서버 중계)

**IT1 모델·광역 타격·파편 물리:** 새 PC 주소는 `/test/building/?mode=mono&key=<접속키>`다. 기존 폰 보정/측정·‘PC 화면으로 보내기’ 그대로 사용하며 근사좌표를 모델에 연결한다. 마우스 시험·전체낙하·힘/범위/파편거리 조정도 가능하다. 기존 상자 PC 화면은 아래 주소로 유지한다. [모델 시험 실행/계약](BUILDING_FRAGMENT_TEST.md)을 따른다. 실폰 정합·추적오차 검증은 별도다.

1. PC 브라우저에서 `https://<PC 주소>:8443/test/mono3d/view.html?key=<접속키>`를 연다.
2. 폰에서 `/test/mono3d/`를 4단계 **측정**까지 진행한다. 측정 카드의 **PC 화면으로 보내기**가 켜져 있으면(기본) 자동으로 연결된다. 상태가 "✓ PC 화면 1개가 보는 중"이면 된다.
3. PC 화면 구성:
   - 왼쪽: 폰 영상(약 5장/초, 폭 480px JPEG)에 마커·건물·뼈대·손목을 겹쳐 그린다.
   - 가운데: 마우스로 돌려 보는 3D 보기. 바닥 격자(0.5m)·마커·건물·폰 위치·몸 관절·손목 궤적을 그린다. 타격하면 건물이 흔들리며 빨개지고 파편이 튄다.
   - 오른쪽: 타격 횟수와 좌표. 타격음은 기본 활성 상태이며 **화면을 한 번 클릭**하면 브라우저 오디오가 시작된다. **소리 끄기/켜기**로 음소거를 전환한다.

폰의 실제 측정 단계에서 손목 3D 추정의 건물 진입을 타격으로 수락하면 충격·붕괴·잔해음이 난다. PC도 새로 전달받은 유효 타격에 같은 효과음을 낸다. 보정·카운트다운 안내는 기존의 짧은 삐 소리를 유지한다. 초기 접속·재접속의 누적 타격 횟수와 중복·무효 프레임은 소리를 다시 내지 않는다. 1대 경로는 계속 `mono_approx`이며 다중 시점 실측 3D로 표시하지 않는다.

수락된 같은 타격에 충격광·확장하는 충격파·회전하는 잔해·먼지·짧은 건물 반동을 표시한다. 폰 AR 영상, PC 영상과 가운데 3D 보기에서 마커 좌표의 타격점을 각각 투영한다. 화면 밖으로 지나간 빠른 타격의 연출 위치는 건물 범위로 제한한다. 이 연출은 추적·타격 판정·점수·건물 손상 메시지를 바꾸지 않는다. 효과는 1.4초 뒤 사라지고 최대 3회·72개 입자만 유지한다. 움직임 줄이기 설정에서는 잔해 비행과 반동·충격광을 생략한다.

자동 검증은 `npm run test:ar`로 실행한다. 정적 서버와 합성 카메라/관절·3D 메시지를 사용하며 실제 브라우저 오디오 신호, 화면 렌더링·중복/재접속/음소거·수명을 확인한다. 실제 장비·청취·정합·성능 결과와 구분한다. [검증 요약](asset-validation/ar-feedback/summary.json)을 참고한다.

중계 경로는 `/ws/test/mono3d`(`backend/test_mono3d.py`)다.
- `role=phone`은 폰 하나만 받는다. 새 폰이 연결되면 이전 폰을 끊는다. `role=viewer`는 여러 개를 받는다.
- 메시지 종류는 `mono3d_calib`(보정·건물·몸 배율, 바뀔 때만), `mono3d_frame`(약 30회/초, 관절 3D·2D·타격), `mono3d_jpeg`다.
- 새 `body.depth_reference{version:marker_center_v1,point_m:[0,0,0],ankle_height_m,floor_bias_m,stand_tolerance_m}`를 보정과 기록JSON에 포함한다. 몸/깊이 기준이 바뀌면 서버는 이전 손목 궤적을 초기화한다. 발목 미검출 프레임은 `valid:false`이며 PC도 손목 타격/동적파편 접촉을 중지한다. 새 서버의 모델 깊이 허용 기본은0m이고 수동으로만 늘릴 수 있다.
- 1대모델PC의사람뒤가림을위해 기존Pose생성시에만`outputSegmentationMasks`를활성화한다(기타카메라는기본OFF). 추론캔버스를고정해 같은프레임의JPEG·사람윤곽·보정관절깊이를묶는다. `mono3d_jpeg.occlusion{encoding:camera_z_mm_rg16_alpha_v1,width,height,data}`는 PNG의R/G에카메라Z깊이mm를16비트로,알파에윤곽을담는다. mm는저장단위이지정확도주장이아니다. 최대192×384/약5Hz이며 원래JPEG메시지/접속보호/512KB제한안에서전달한다. 유효깊이/윤곽이없으면null이다. MediaPipe마스크는복사뒤해제하고 PC텍스처는교체/만료시해제한다. [건물시험](BUILDING_FRAGMENT_TEST.md)의가림ON/OFF와한계를따른다.
- 기존 상자뷰어 경로는 종류·크기(512KB)를 검사하고 `source: mono_approx`를 붙여 전달한다. 새 `model=it1` 뷰어는 유효/유한 근사손목으로 모델 접촉도 계산한다. 이 경로가 카메라 삼각측량을 하거나 영구 저장을 하는 것은 아니다.
- 느린 PC에는 최신 프레임·영상만 보낸다. 늦게 연 PC 화면도 마지막 보정·프레임·영상을 바로 받는다.
- 일반 접속 키로 보호한다(공개 경로 아님). 기존 방·게임·`/ws/pose` 경로와 섞이지 않는다.

## 한계

- 카메라 쪽 앞뒤(깊이) 방향 오차가 가장 크다. 타격 방향이 카메라 기준 옆이 되도록 배치하는 것이 유리하다.
- 렌즈 왜곡을 보정하지 않고, 화각은 근사값이다. MediaPipe worldLandmarks의 축 방향(카메라 정렬, y 아래)은 가정이다.
- 실폰·실제 위치 대조 정확도는 측정하지 않았다. 사진 1장 기반 브라우저 시험과 합성 단위 시험만 수행했다.
- 2026-11-12 마커 기준 보정은 합성 앞뒤이동/손목 좌표·발목 가림/복구·잘못된 위치/한발/흔들림 거부를 검사했다. 카메라1대의 팔 자체 깊이는 여전히 MediaPipe 모델 추정에 의존한다. 마커 중심 위라는 자세 가정·평평한 바닥/접지·폰 고정이 필요하며 렌즈/가림/빠른동작 오차를 제거했다는 뜻은 아니다.

## 2026-11-16 사람 3D 표시·사람 앞 가림

마커 기준 3D 화면은 관측한 코·어깨·팔꿈치·손목·골반·무릎·발목을 사용해 머리·몸통·팔다리를 그린다. 실제 사람 스캔/사진 텍스처가 아닌 관절 기반 사람 모형이다. 없는 관절은 만들지 않고 해당 부위를 숨긴다. 입력 만료(500ms)·연결 종료·보정 변경 시 남은 모형을 정리한다. 건물의 초기허리70% 고정·물리/점수는 그대로다.

PC 영상의 사람 뒤 가림은 기본 ON이다. MediaPipe 사람분할 윤곽과 관절의 카메라Z 깊이를 결합한 깊이 전처리로 뒤쪽 모델만 가리며 앞쪽 모델·윤곽 밖은 보존한다. PC는 동적 파편도 가린다. 깊이는 같은 JPEG에 깊이PNG로 동봉한다.

3대 폰도 기존 Pose의 분할 출력을 켜며 추가 추론 모델은 쓰지 않는다. 최근 융합 결과가 200ms 이내이고 네 몸통 관절이 필수로 있고 보이는 관절들이 현재 랜드마크와 재투영 오차 max(12px,영상대각2.5%) 안에서 맞을 때만 그 깊이를 사용한다. 서버가 교정한 좌우 라벨 반전도 반영한다. 늦거나 불일치하면 가림을 보류한다. PC에서 카메라 프레임이 순차 도착해 잠깐 1시점만 정렬됐을 때는 200ms 이내 최근 유효 몸통을 유지하고, 유효 2시점 이상에서 추적 무효가 확인되면 즉시 해제한다. 실제 관절 누락은 복원하지 않는다.

사람 표면 깊이는 관절 깊이에서6cm를 보정한 근사이고 실제 깊이 센서가 아니다. 실폰의 가림 경계/빠른 동작/조명/지연·세 폰 추가 부하는 미검증이다. 적용은 build:building-test 후 서버 재시작·PC/폰 새로고침이며, 3대 폰은 분할 출력 옵션을 새로 적용하도록 카메라를 다시 켠다.

## 2026-11-16 실사용 후속: 3대 몸보정 생략·가림 진단·발목 범위

3대 폰은 카메라→마커→보내기 순서로 진행한다. 신규 사람 몸보정 화면으로 자동 이동하지 않고 PC의 몸보정 시작 버튼도 숨긴다. 서버는 구형 폰의 requires_body_calibration=true 요청도 필수 단계로 강제하지 않는다. 기존 선택된 고정 건물 크기를 사용한다. 카메라별 실제 마커 보정/저장값 재사용은 필요하며 없는 K/R/t를 자동 생성하지 않는다. 이전의 필수 3대 몸보정 설명은 이력이다.

1대 가림은 타격용 result.valid에만 묶지 않는다. 발목이 안 보여 feet_required_for_depth가 된 경우, 이미 몸 보정이 있고 어깨/골반과 worldLandmarks가 유효하면 발 관측을 제외한 torso_scale 추정으로 가림용 깊이를 계산한다. visual_torso_only/collision_usable=false로 구분하고 타격 좌표·서버 추적·점수에는 사용하지 않는다. JPEG의 occlusion_valid/occlusion_reason으로 PC에도 시각 가림의 독립 유효성을 전달한다. PC는 깊이 패킷 500ms 만료·잘못된 PNG·연결/보정 변경을 정리한다.

폰의 새 상태 문구는 윤곽 부재/읽기 실패, 깊이 부족, 가림 준비 픽셀 수, 시각용 몸통 추정 여부, 좌우 발목 검출 여부를 알려 준다. 모델 번들/폰 스크립트 캐시버전을 올렸다. 서버 재시작과 폰/PC 새로고침, 폰 카메라 재시작 후 확인한다. 이 수정은 코드에서 발견한 가림 중단 조건을 보완한 것이며 사용자의 실제 폰 실패 원인을 재현/확정한 것은 아니다.

발목은 1대/3대 입력·3D 사람 표시·1대 깊이 기준에 포함된다. 3D 건물 FragmentTest.update의 실제 타격 관절은 여전히 양 손목이다. 별도 phone_2d 게임은 앞서 발차기 경로를 연결했다. 발목 추적과 3D 발차기 타격 완료는 구분한다.
