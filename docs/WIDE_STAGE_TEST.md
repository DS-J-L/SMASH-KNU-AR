# 3대 가로 넓은 무대 시험

2026-11-16 사용자 결정: 1대 근사 깊이 판정이 쓸 만하므로, 3대를 사람 주위 60~120°로 둘러싸는 대신 **일정 간격으로 가로로 나란히** 두고 무대를 넓힌다. 폰마다 자기 마커로 1대 방식 깊이를 계산하고, 서버는 마커 간격만큼 좌표를 옮겨 하나의 무대로 합친다. **삼각측량은 하지 않는다.** 결과는 `source: mono_approx`이며 P3의 다중 시점 3D 완료 근거가 아니다. 기존 3대 삼각측량(`/test/building/`, `/test/multi3d/`)과 1대(`?mode=mono`) 경로는 그대로 둔다.

판정 폰 2대 + 반대편 화면 폰 구성은 [DUO_STAGE_TEST.md](DUO_STAGE_TEST.md)에 있다(같은 서버 코드, 경로 `/ws/test/duo3d`).

## 배치

```
        ID0 마커            ID1 마커            ID2 마커        ← 무늬 위쪽(+Y)이 모두 폰에서 먼 쪽
   x = -간격               x = 0              x = +간격        ← 마커 중심 사이 간격 (기본 1.5m)
        ▲                   ▲                   ▲
       C0 폰               C1 폰               C2 폰          ← 각 폰은 자기 마커 앞에 고정
```

- 마커: `assets/markers/floor-direction-id0-a4.pdf`, `floor-direction-id1-a4.pdf`, `floor-direction-id2-a4.pdf`를 실제 크기 100%로 인쇄한다. 검은 사각형 한 변이 200mm인지 잰다. 세 장 모두 같은 크기여야 한다. ID1/ID2는 `python tools/make_floor_markers.py`로 ID0과 같은 도안으로 만들었고 OpenCV로 번호를 확인했다(`--check`로 재확인).
- 세 마커를 왼쪽부터 ID0·ID1·ID2 순서로 **한 직선 위에, 같은 방향으로, 같은 간격으로** 놓는다. 간격·방향이 틀리면 구간이 바뀔 때 손 위치가 튄다. 줄자로 마커 중심 사이를 잰다.
- 각 폰은 자기 마커가 화면 가운데~아래에 크게 보이고 사람 전신이 들어오도록 고정한다. 옆 구간이 조금 겹쳐 보이는 것은 괜찮다. 판정에는 사람에게 가장 가까운 마커의 폰 하나만 쓴다.

## 실행

1. 서버를 재시작한다. 새 경로 `/ws/test/wide3d`를 추가했다.
2. PC: `https://<PC 주소>:8443/test/building/?mode=wide&key=<접속키>`. 오른쪽 **마커 간격**에 실제로 잰 값(0.5~3m)을 넣고 **간격 적용**을 누른다.
3. 폰 3대: `https://<PC 주소>:8443/test/mono3d/?stage=wide&camera=C0&key=<접속키>` (C1, C2도 같은 방식). 첫 화면에서 번호를 바꿀 수도 있다. 번호를 바꾸면 페이지가 다시 열린다.
4. 각 폰에서 카메라 → 고정 → **마커 자동 인식**(자기 번호 마커만 인식, 옆 마커는 무시) → 초록 테두리 확인 → **몸 보정**(그 폰의 마커 중심에 두 발 사이를 맞추고 직립) → 측정. 수동 모서리 찍기도 마커 무늬로 방향을 읽으며, 무늬가 자기 번호가 아니면 보정하지 않는다.
5. PC 위쪽에 C0 | C1 | C2 영상이 가로로 이어지고, 무대 상태에 `★판정` 폰이 표시된다. 건물을 손/발로 친다.

## 계산 방식

- **좌표:** 폰 n은 마커 n 기준 좌표(원점 마커 중심, +X 오른쪽, +Y 먼 쪽, +Z 위)를 그대로 보낸다. 서버는 x에 `(n-1) × 간격`을 더한다. 카메라 자세는 `t' = t − R·o`, `C' = C + o`(o = [오프셋,0,0])로 바꿔 PC 영상 합성에 쓴다. 회전은 바꾸지 않으므로 세 마커의 방향이 같아야 한다.
- **판정 폰:** 최근 400ms 안의 유효 프레임 중 사람 기준점(발/몸통 anchor)이 **자기 마커에 가장 가까운 폰**이 판정한다. 다른 폰이 0.15m 이상 더 가까워질 때만 넘긴다(경계에서 왔다 갔다 방지). 넘길 때 궤적 기준점을 지워 두 폰의 서로 다른 추정을 한 궤적으로 잇지 않는다. 판정 폰이 아닌 폰의 프레임은 PC 표시(영상·가림)와 아래 관절 대체에만 쓴다.
- **가려진 관절 대체:** 판정 폰에 손목·발목(가시도 0.5 미만이면 폰이 보내지 않음)이 없으면, 같은 사람을 보는 옆 폰의 같은 관절을 무대 좌표 그대로 빌린다. 조건은 옆 폰 프레임이 150ms 이내이고 옆 폰의 사람 기준점이 판정 폰의 기준점과 0.4m 이내인 것이다(다른 사람 배제). 여럿이면 사람이 마커에 더 가까운 폰을 쓴다. 관절마다 출처 폰을 기록하고 **출처가 바뀌면 그 관절의 궤적만 끊는다.** 두 폰의 추정 차이로 생긴 순간 이동을 휘두름으로 판정하지 않기 위해서다. 따라서 출처가 바뀌는 순간 진행 중인 휘두름 하나는 놓칠 수 있다. 엉덩이(서 있는 위치 판정)는 빌리지 않는다. PC 상태 줄에 `가려진 관절은 옆 폰 값 사용(오른손←C2)`처럼 표시하고, 모델 상태 `stage.borrowed`와 `wide3d_frame.borrowed`에 `{관절: 카메라}`를 싣는다.
- **무대 기본 옵션(2026-11-20, 사용자 결정):** 넓은 무대·2대 무대 PC 화면은 `건물을 부수면 자동으로 다음 건물` 켬, `광역 타격 · 건물 전체 날리기` 끔, 물리 `남은 건물과 충돌` 끔, `지지 상실 붕괴` 끔으로 시작한다. 전체 날리기·붕괴는 서버 무대가 처음 만들어질 때 꺼지고(PC 체크는 서버 상태를 따름, 다음 건물로 넘어가도 유지), 나머지 둘은 PC 페이지 기본값이다. 1대·3대 삼각측량 화면 기본값은 그대로다.
- **건물(2026-11-20 변경, 사용자 결정): 무대 세트 하나에 건물 하나**, 타격감을 위해 크게. 높이를 캠퍼스 높이 순서대로 **1.0~1.2m**로 맞추고, 바닥 면은 **가로 2.0m × 깊이 1.5m** 안에 들어가야 한다. 너무 긴 축만 따로 눌러 비율을 바꾸되 최대 절반까지만 누르고, 그래도 넘으면 건물 전체를 줄인다. 결과 높이가 0.6m보다 낮은 아주 납작하고 긴 건물 5개는 뺀다 → 61개 중 **56개, 56세트**(높이 중간값 약 1.0m, 대부분 가로 2.0m·깊이 1.5m). 건물은 무대 가운데(x=0)에 놓인다. 무대 폭(간격×구간 수)이 건물보다 좁으면 건물 전체를 줄인다(`fit_scale`). 파편 꼭짓점·충돌체·화면 배율이 축별 `[가로, 높이, 깊이]` 배율을 같이 쓴다(모델 노드에 회전이 없어 비틀림 없음). 아래 11-18 규칙(폭 0.7~0.8m, 세트당 2~3개)은 대체됐다.
- **건물(2026-11-18 변경):** 소구역 대신 **무대 세트**를 쓴다. 대상 건물 61개를 각자 **가로 폭 0.7~0.8m**로 맞춘다(캠퍼스에서 넓은 건물일수록 0.8m). 높이·깊이는 그 건물의 원래 비율을 따른다. 그다음 캠퍼스 순서대로 무대 폭(간격×3) 안에 축소 없이 들어가는 만큼 한 줄로 묶는다. 건물 사이는 최소 0.25m이고, 마지막 세트가 1개뿐이면 앞 세트와 나눈다. 간격 1.5m와 2m 모두 4개씩 16세트였다(아래 높이 하한 적용 전). 몸 보정은 크기를 바꾸지 않는다. 간격을 바꾸면 세트를 다시 묶고, 보던 세트의 첫 건물이 든 세트로 이어 간다. 목록은 `/api/test/building-scenes?kind=stage&layout=wide|duo&spacing=<m>`이다. 장면 id는 `wide:<세트 id>:<간격mm>:<호환용 높이mm, 무시>`이고, 서버 충돌체와 PC 렌더가 같은 값으로 만든다.
  - 높이 하한(2026-11-18 추가, 사용자 A안): 폭을 맞춘 뒤 0.5m보다 낮으면 비율을 유지한 채 건물 전체를 0.5m 높이까지 키운다(폭도 같이 넓어짐). 그렇게 키웠을 때 폭이 1.5m를 넘는 아주 낮고 긴 건물은 무대에서 뺀다. 61개 중 30개가 남고, 모든 건물이 0.5m 이상이다(폭 0.7~1.5m, 높이 0.5~1.13m). 간격 1.5m(넓은 무대)는 11세트, 2m(2대 무대)는 12세트이고 한 세트에 2~3개다. 세트마다 건물 수와 폭이 달라 위치도 세트마다 다르다(가운데 정렬, 사이 0.25m 이상).
  - 하한을 두기 전에는 61개를 모두 썼고, 높이 중간값이 약 0.24m, 최저가 약 0.06m였다.
  - (이전) 소구역 하나를 펼치고 최고 높이를 처음 몸 보정한 폰의 허리×0.7로 맞추던 방식은 이 변경으로 대체했다.
- **판정 규칙:** 기존 `FragmentTest`(1대 근사 모드, 깊이 허용 기본 0m, 손목·발목, 겹침 빠른 동작, 발차기 0.2m·1.5m/s)를 그대로 쓴다. 넓은 무대의 광역 타격 기본 반경은 0.6m로, 한 번에 한 구간의 건물만 날린다(PC에서 바꿀 수 있음).

## 연결 규격 (`/ws/test/wide3d`)

- `role=phone&camera=C0|C1|C2`: 번호마다 폰 하나. 1대 페이지의 `mono3d_calib`/`mono3d_frame`/`mono3d_jpeg`를 그대로 보낸다. `mono3d_calib.marker_id`는 카메라 번호와 같아야 하며 다르면 `error{code:'marker_id_mismatch'}`. 서버는 `mono3d_status{viewers,camera,owner}`를 보낸다.
- `role=viewer`: `multi3d_model_*` 명령(복원·마우스·광역·깊이 허용·붕괴), `multi3d_model_scene{scene_id:<무대 세트 id, 예: s04>}`, `wide3d_stage_config{spacing_m}`. 자유 배치 `multi3d_model_config`는 거부한다(마커를 옮기거나 간격을 바꾼다).
- 서버 → PC: `multi3d_calib`(무대 좌표로 옮긴 R·t·C, `marker_offset_m`), `multi3d_jpeg`, `multi3d_phone_left`, `wide3d_frame{camera_id,valid,joints(무대 좌표, 판정 폰은 빌린 관절 포함),owner,borrowed}`, `wide3d_status{cameras{connected,calibrated,body,valid,marker_x_m},owner,spacing_m}`, `multi3d_model_state{model_test{...,stage{zone_id,spacing_m,height_m,owner,borrowed,reference_camera}}}`.
- 접속 키로 보호한다. 저장은 하지 않는다.

## 검증과 한계

- 자동 시험(2026-11-16, 합성 입력): `tests/test_wide3d.py` 10개(판정 폰 손목 가림 시 옆 폰 값으로 타격·다른 사람의 관절은 빌리지 않음·출처 전환 순간 이동은 타격 아님(궤적 끊기를 빼면 오판하는 것 확인)·오래된 옆 폰 값 미사용, 마커 번호 불일치 거부·자세 이동·관절 이동·가까운 폰 선택/전환 여유·판정 폰만 타격·첫 몸 보정 고정/재보정·간격/구역 변경·자유 배치 거부·전 구역 무대 폭 안 배치), `tests/test_auto_marker.mjs`(한 화면의 ID0/1/2 중 자기 번호만 인식, 다른 번호 거부), `tests/browser/building-wide.spec.js` 2개(세 영상 가로 한 줄·마커 3개·같은 점의 좌우 투영·C1 판정 타격 시 가운데 건물 하나만 파괴·간격 2m 재배치·C1 손목 가림 시 `오른손←C2` 표시, 폰 페이지 번호/마커 ID).
- 미검증: 실폰 3대, 실제 가림에서 MediaPipe가 가시도를 높게 준 채 추측 위치를 내는 경우(이때는 대체하지 않고 판정 폰의 추측값을 쓴다), 옆 폰 깊이 차이로 인한 대체 관절 위치 오차, 실제 마커 간격·방향 오차가 구간 전환에 주는 영향, 폰마다 다른 근사 깊이의 경계 튐, 세 폰 동시 부하/네트워크, 몸 보정을 세 번(폰마다) 해야 하는 운영 부담. 근사 깊이 특성상 카메라 쪽 앞뒤 오차가 가장 크다.
- 구간 경계에서는 두 폰의 추정이 다를 수 있어 판정 폰을 넘길 때 궤적을 끊는다. 경계를 지나며 친 한 번의 휘두름은 놓칠 수 있다.
- 자동 시험 갱신(2026-11-18, 무대 세트): `tests/test_wide3d.py`에서 세트가 61개 건물을 순서대로 한 번씩 담는지, 각 폭이 0.7~0.8m인지, 축소 없이 무대 폭에 들어가는지, 잘못된 세트 id를 거부하는지 확인한다. 몸 보정은 크기를 바꾸지 않고, 간격 변경 시 같은 첫 건물의 세트로 이어 가며, 타격 시험은 실제 건물 위치(x≈0.5)를 친다. `building-wide.spec.js`는 세트 16개, 폭 표시, 건물 위치 타격을 확인한다.
- 자동 시험 갱신(2026-11-18, 높이 하한): 30개 건물만 쓰고, 모든 건물이 0.5m 이상, 0.5m로 키운 건물만 0.8m보다 넓고, 1.5m 넘는 건물은 제외되는지 확인한다. 세트는 축소 없이 무대 폭에 들어가야 한다. `building-wide.spec.js`는 세트 수를 API와 비교하고, 손 타격 문구 확인 중에는 파편 충격 파괴를 끈다(큰 건물이 무너지며 생긴 파편 충격이 마지막 이벤트 문구를 덮어썼기 때문).
