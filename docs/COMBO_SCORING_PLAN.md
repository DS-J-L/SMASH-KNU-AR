## 1. 사용자 요구와 해석

| 구분 | 내용 |
| --- | --- |
| 명시 요구 | 이전 break 행동으로부터 4초 안에 추가 파괴하면 콤보 유지·증가. 타격 점수 배율은 0.1씩 증가. |
| 명시 요구 | 건물 교체 시 기존 2초 무적 중 **1초만** 콤보 남은 시간 게이지를 정지. |
| 명시 요구 | UI는 컴퓨터의 플레이 화면에 표시. 이번에는 설계와 이해한 방향 설명까지만. |

위 '이번 해석/세부 제안'은 사용자에게 설명해 검토받을 내용이며 인수 확정 사실이 아니다. 별도 철거 보너스·속도 보너스를 자동 추가하지 않는다. 한 판 60초는 앞선 제안값이며 이번 사용자가 새로 확정한 값으로 기록하지 않는다.

## 2. 현재 코드와 설계의 차이

- [무대 설정](../backend/test_wide3d.py)은 일반 모드의 광역 타격·지지 상실 붕괴를 기본으로 끈다. duo는 `sweep=True`라 손발 궤적이 통과한 여러 파편을 제거한다.
- [파편 처리](../backend/fragment_test.py)는 새 고유 제거 파편 수만 점수에 더하고 `snapshot.score=len(removed)`를 제공한다. 현재 콤보나 가중 점수는 없다. 건물/epoch 교체 때 제거 집합과 이 원점수가 초기화된다.
- 기존 `swing_id/swing_start`는 연속 파괴 간 공백 400ms를 기준으로 묶는 시간 휴리스틱이다. 사람의 펀치/킥 개수를 인식하는 기능이 아니다. 최초 접촉만 콤보를 올리고 이어지는 파편 제거는 같은 배율로 계산하는 데 참고한다. 실제 빠른 연속 타격이 합쳐지는 정도는 실폰에서 확인해야 한다.
- 최신 서버의 `spawn_guard_ms`는 새 건물 생성 후 몸 타격을 2초 막는다. 콤보 정지 기능은 없다.
- [PC 표시](../frontend/building-test/main.js)의 `viewHud`는 V 전체화면에 파괴율·건물별 시간을 표시한다. 현재 자동 교체 대기는 별도 클라이언트 타이머다. 이 설계에서는 정지 시간을 실제 서버 무적 구간에만 연결하며 교체 전 대기를 정지 구간으로 계산하지 않는다.
- [기존 게임 세션](../backend/game_sessions.py)은 video_check/phone_2d 경로다. duo의 한 판/콤보 지원이 이미 있다고 가정하지 않는다.

## 3. break 행동·콤보 판정

1. 서버가 플레이 중·유효 입력·현재 대상/epoch·무적 종료를 먼저 검사한다. 거부된 입력은 파편·점수·콤보를 바꾸지 않는다.
2. 새 제거 파편이 1개 이상 있는 행동만 break다. 헛스윙·이미 제거된 파편 재밀기·중복 이벤트·미리보기는 콤보 증가/4초 갱신이 없다. 기존 파괴 유효 조건은 이 문서에서 낮추지 않는다.
3. 최초 break 또는 만료 후 break는 `C=1`. 직전 실제 break부터 계산한 유효 경과 시간이 **4000ms 이하**이면 새 행동에서 `C=C+1`. 4000ms는 유지, 4001ms는 새 1 HIT다.
4. 같은 행동에서 이어지는 파편 제거는 `C`를 올리지 않고 그 행동에 고정한 배율로 추가 계산한다. 새 파편이 제거된 마지막 시각으로 4초 기준은 갱신한다. 빈 이벤트로는 갱신하지 않는다.
5. 행동 키는 `(session_id, target_instance_id, epoch, action_id)`다. `action_id`는 서버에서 부여하고 기존 swing_id와 연결하되 충돌/재사용을 막는다. 같은 서버 처리 회차의 양손/양발 파괴는 하나의 행동으로 집계하는 초기안이다. 사람이 실제로 두 번 친 것인지는 시간 휴리스틱의 한계로 남긴다.
6. 직접 제거와 같은 수락 타격에서 동기적으로 확정한 지지 상실 제거는 같은 행동에 포함한다. 화면에서 파편이 나중에 떨어지거나 소리가 재생되는 것은 새 break가 아니다. 원인 행동이 확인되지 않은 시험용 물리 release/마우스/키보드는 실제 콤보 기록에 넣지 않는다.
7. 자동 건물 교체는 세션 점수·콤보를 유지하지만 옛 행동은 새 epoch로 이어 붙이지 않는다. 다음 건물에서 별도로 수락된 새 행동이어야 한다. 수동 복원/장면·모드 변경은 경쟁 기록을 중단/초기화하는 별도 운영 명령이며 콤보 유지 혜택을 만들지 않는다.

## 4. 타격 점수 계산식

기존 **새 파편 1개당 기본 1점**을 바탕으로 다음을 제안한다. 제거 범위·철거 기준은 점수 배율 때문에 커지지 않는다.

```text
D = 해당 행동에서 이번에 새로 제거한 고유 파편 수
C = 해당 행동에 배정된 연속 타격 번호(1부터 시작)
기본 타격 점수 B = D × 1점
콤보 배율 M(C) = 1 + 0.1 × (C - 1)
이번 타격 점수 H = B × M(C)
한 판 점수 S = 모든 수락 타격 H의 합
```

| 연속 행동 | 신규 파편 D | 배율 | 타격 점수 H |
| --- | --- | --- | --- |
| 첫 타격 | 10 | ×1.0 | 10점 |
| 4초 이내 다음 타격 | 10 | ×1.1 | 11점 |
| 다시 4초 이내 다음 타격 | 10 | ×1.2 | 12점 |
| 4초 초과 뒤 다음 타격 | 10 | ×1.0 | 10점 |

첫 세 행동의 합계는 33점이다. 예를 들어 3 COMBO에서 새 파편 12개면 14.4점이다. 콤보 유지에 따른 속도 보상은 배율에 반영되므로 별도의 시간 보너스/철거 1000점 보너스는 이 식에 넣지 않는다.

부동소수점 누적/타격별 반올림을 피하려고 서버는 **0.1점 단위 정수**로 저장한다.

```text
awarded_score_units = D × (10 + C - 1)
session_score_units += awarded_score_units
화면 점수 = session_score_units / 10
```

소수부가 0이면 정수, 그 외는 소수 첫째 자리까지 표시한다. 기존 건물별 `score`/파편 로그는 원점수로 보존하고, 세션 가중 점수는 `game_score_units`로 별도 제공한다. 모델별 파편 수가 다른 문제는 여전히 있으므로 비교용 세트 목록·순서·배율·철거 임계값·일반/슈퍼 모드를 같은 설정 버전으로 고정한다. 슈퍼와 일반 기록을 합쳐 비교하지 않는다.

## 5. 4초 시계와 교체 중 1초 정지

**멈추는 것은 콤보 시계뿐이다.** 2초 무적은 유지하고, 한 판 제한 시간은 이 혜택 때문에 멈추지 않는다. 보호 시간을 1초로 줄이거나 4초로 게이지를 다시 채우는 규칙도 아니다.

```text
유효 경과 = 서버 단조 시계 경과 - 그 사이 실제 콤보 정지 구간 길이
콤보 남은 시간 = max(0, 4000ms - 직전 break 이후 유효 경과)
게이지 비율 = 콤보 남은 시간 / 4000ms
```

서버의 정상 철거→다음 대상 전환 ID마다, 실제 2초 무적의 **앞 1000ms 구간**을 정지 구간으로 1회 등록한다. 끝나지 않은 구간은 지금까지 흐른 길이만 뺀다. 겹치는 정지 구간은 합집합으로 계산하고, 전환 전에 이미 만료된 콤보는 되살리지 않는다. 새 대상이 PC에서 준비/표시되기 전에 보호 타이머만 끝나지 않도록 렌더/충돌체 준비 ACK와 시작 기준을 맞추는 작업은 구현 선행 조건이다.

### 시간 예시 A — 마지막 타격 직후 교체 시작

| 실제 경과 | 상태 | 콤보 남은 시간 |
| --- | --- | --- |
| 0초 | 철거를 만든 break·교체/2초 무적 시작 | 4.0초 |
| 1초 | 콤보 정지 1초 종료, 무적은 1초 남음 | 4.0초 |
| 2초 | 무적 종료·다음 타격 가능 | 3.0초 |
| 4초 | 추가 break가 없었음 | 1.0초 |
| 5초 | 정확히 경계에서 break 수락 시 유지 | 0.0초 직후 다시 4.0초 |
| 5.001초 | 앞선 break가 없었다면 만료 | 0.0초·다음은 ×1.0 |

### 시간 예시 B — 교체 전 대기가 있는 현재 경로

마지막 break 후 교체 전 대기 3초 + 새 대상 무적 2초라면, 그중 1초만 정지하므로 무적 종료 때 이미 유효 4초 경계다. 여기에 모델 로딩/반응 시간이 더해지면 콤보가 끊긴다. **현재 별도 교체 대기를 유지한 채 1초 정지만 추가하면 건물 사이 콤보를 잇기 어렵다.**

따라서 다음 모델을 미리 준비하고 철거 피드백/새 대상 보호를 겹쳐, 철거 후 별도 3초 대기를 더하지 않는 전환을 권한다. 2초 무적 자체는 유지한다. 기존 파괴 연출의 완전한 재생·옛 파편과 새 모델의 시야는 구현 후 비교할 항목이다. 로딩/장비 장애 시간을 모두 이 1초 혜택에 섞어 빼지 않는다. 장애 일시정지/경쟁 기록 취소는 별도 세션 정책이며 반복 전환·재접속으로 시간을 무제한 늘리지 못하게 한다.

## 6. PC 플레이 UI

PC에서 보는 V 영상 안쪽에 HUD를 겹친다. 운영 설정 패널/폰 화면을 주 표시 위치로 삼지 않는다. PC의 일반 플레이 보기와 브라우저 전체화면 모두 같은 HUD를 사용한다.

```text
남은 시간 00:42                      총점 128.4

                  6 COMBO  ×1.5
              콤보 ━━━━━━━░░░  2.8초
               [교체 중에는: 잠시 정지]

            V 실제 영상 + 부분 파괴 건물

       철거 4개     현재 파괴 45% / 목표 70%
```

- 첫 타격은 `1 HIT ×1.0`, 두 번째부터 `2 COMBO ×1.1`로 표시. 성공한 새 행동에서 짧게 강조하고 `+이번 타격 점수`를 표시한다. 같은 휘두르기의 후속 파편은 같은 팝업 합계만 갱신한다.
- 4초 게이지는 서버 기준 값을 부드럽게 감소시킨다. 남은 시간이 짧으면 텍스트/표시 변화도 함께 주고 색만으로 구별하지 않는다.
- 정지 1초 동안 막대 길이/숫자를 유지하고 `콤보 잠시 정지`를 표시한다. 무적 남은 시간은 따로 계속 감소한다. 다음 1초는 `새 건물 준비 중` 상태에서 콤보 게이지가 다시 줄어든다.
- 콤보 만료 시 배율 ×1.0/`콤보 종료`를 잠깐 표시하고 다음 유효 행동을 기다린다. 이미 획득한 한 판 점수는 줄지 않는다.
- HUD는 타격 부위/손발과 바닥 마커를 가리지 않는 상단 영역에 배치한다. 모바일 폰은 기존 입력/진단 역할을 유지한다. 소리/번쩍임은 콤보 판정과 독립이며 음소거/축소 동작에서도 숫자·게이지는 읽을 수 있어야 한다.
- 결과 화면에는 한 판 점수·철거 수·최대 콤보·최대 배율을 표시한다. 남은 시간·승패/순위 정책은 한 판 설계에서 따로 확정한다.

## 7. 제안 계약·구현 순서

아래 필드는 아직 제공되는 API가 아니다. 실제 구현 시 [DATA_CONTRACT.md](DATA_CONTRACT.md)를 함께 갱신한다.

| --- | --- |

## 9. 결정 대기·다음 단계

사용자에게 특히 확인받을 해석은 **같은 건물에서도 추가 파괴를 만든 별도 타격이면 콤보 증가**, 첫 행동 ×1.0/다음 ×1.1, 한 휘두르기의 연속 파편은1회라는 점이다. 기본점수1점 유지·무적 앞1초 정지·상한 없음은 이번 수식/상태를 구체화한 제안이다.

현재 설계 요청에는 막힘이 없다. 제품 구현/실기기 인수는 미완료다. 기존 미커밋 게임화 문서7개를 다른 작업과 섞지 않도록 최신 main 기반 별도 작업 트리에서 이 문서와 계획 연결만 작성했다. 과거 고정3개/콤보 후순위 제안은 이 요청 범위의 후속 설계로 대체하지만 과거 기록은 지우지 않는다. 팀원의 실제 착수/가용 일정은 확인하지 않았다.
