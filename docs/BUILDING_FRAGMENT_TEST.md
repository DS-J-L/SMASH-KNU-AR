## 2026-11-16 현재 기준 — 최초 허리 고정

- 1대는 기존 마커 위 직립 몸 보정 완료 때 허리 기준을 한 번 만든다. 허리는 기존 키×0.6 추정(0.6~1.3m 제한)이며 실측 센서가 아니다. IT1 단독 높이를 이 값으로 정하고 바닥 마커 (0,0)에 고정한다. 이후 움직임/앉기/키 추정 변화/복원으로 자동 크기·위치를 바꾸지 않는다. 명시적으로 몸 보정을 다시 하면 새 기준을 만든다.
- 구역은 2개를 앞에, 가장 높은 1개를 뒤에 놓고 전체 바닥 외곽의 중심을 마커에 맞춘다. 2개 구역은 좌우 중앙 배치다. 기존 87개 평균높이0.95m로 정한 공통 축척에 최초 허리/0.95를 한 번 반영한다. 구역 전환은 동일 보정 비율을 사용하므로 같은 건물의 크기는 바뀌지 않는다. 모든 건물 높이가 각각 허리와 같다는 뜻은 아니다. 기존 고정0.95m/가로 일렬 배치 설명은 이전 정책이다.
- 3대 폰은 각자 마커 보정→몸 보정 화면으로 진행한다. 세 폰을 모두 연결한 뒤 한 폰 또는 PC 건물 시험의 '세 폰 몸 보정 시작'을 누른다. 마커 위 직립/양발접지, 코·어깨·골반·발목의 유효 3D와 세 시점, 최소20표본/2.5초 이상 연속 안정성을 확인해 허리를 저장한다. 완료 전에는 새 폰의 실제 손 타격을 중단한다. 재연결/카메라 재보정은 재몸보정을 요구하며 옛 크기를 실시간으로 추종시키지 않는다. 타임스탬프가 없는 구형 합성/재생 테스트 메시지는 호환 경로이며 실기기 완료 근거가 아니다.
- 폰 페이지는 건물과 충돌체를 그리지 않는다. 건물·충돌체·파편은 PC 화면에만 표시한다.
- 측정/몸보정 화면은 전체 원본 프레임을 contain으로 표시해 화면 잘림을 막는다. 전체 건물 외곽이 영상 여백6% 안에 들어오는지 검사하고 부족하면 거리/각도 변경·마커/몸 재보정 안내를 표시한다. 고정된 실제 크기를 유지하므로 가까운 카메라에서 임의로 세 건물을 모두 보장하거나 매 프레임 축소하지 않는다. 넓은 건물 구역은 상당한 촬영 거리가 필요할 수 있다.
- 배포는 npm run build:building-test 후 서버 재시작·폰/PC 새로고침. 실폰 허리/정합 정확도·시야 확보·장시간은 미검증이다.


1대 모드는 IT1 단독과 캠퍼스 8개 대구역을 나눈 **23개 소구역(건물2~3개씩,61개 건물)**을 선택할 수 있다. 고정높이0.5m 미만26개는 시험목록에서 제외한다. 3대 모드는 기존 IT1 단독을 유지한다. 기존 1대 근사/3대 상자 시험과 별도 PC 화면이다. `/test/building/?mode=mono`는 폰1대 근사손목(`mono_approx`), `/test/building/`는 최소2대의 삼각측량 손목(`multi_view_test`)을 사용한다. 같은 물리 옵션을 쓰지만 서버 모델상태는 분리한다. 공통 P3/P4 통과나 실제 AR 정합 정확도 검증을 뜻하지 않는다.

## 점수 — 2026-11-16 사용자 결정

서버 `model_test.score`는 현재 제거된 고유 파편 수다. 직접 파괴와 지지 상실 낙하 모두 파편당 1점이며 이벤트 `points`는 이번에 새로 제거된 파편 수다. `released_ids`에 `unsupported_ids`가 이미 포함되므로 두 배열의 길이를 더하지 않는다. PC는 서버 누적값을 표시하여 같은 이벤트 재수신/재접속에서 중복 가산하지 않는다. 빈자리·이미 떨어진 파편 재밀기는 0점이다. 건물 복원·구역/배율 재설정은 새 라운드로 0점이다. 전체 낙하 버튼과 마우스·물리 연쇄 파괴도 시험 점수에 포함되며 실제 입력 성적과 구분한다. 기존 2D 폰 게임의 100점/부분 파괴 화면 연결은 이번 시험 경로와 별도다.

## 실행

**사람 뒤 가림(1대 영상):** 폰/PC를 새로고침하고 마커·몸보정을 마친 뒤 측정/전송을 켠다. PC의 ‘사람 뒤 건물·파편 가림’은 기본ON이다. 사람의 실제 영상 윤곽 안에서 추정 카메라 깊이보다 뒤쪽에 있는 건물/분리된 파편 부분만 투명하게 만든다. 윤곽 밖이나 사람 앞쪽 파편은 그대로 보인다. 중앙3D보기·충돌/파괴 상태에는 영향을 주지 않는다. ON/OFF로 비교할 수 있다.

폰에서 기존 MediaPipe Pose의 사람분할 출력을1대시험에만 추가한다. 같은 추론용 캔버스의JPEG와 윤곽/카메라깊이PNG를 한 패킷으로 전송한다. 마스크는 최대192×384, 영상과 같은 약5Hz이며 관절의보정된3D를 카메라R/t로 변환한 깊이를 몸통/팔/다리에 보간한다. 관절 중심에서 표면까지6cm 보정은 시각용 근사다. 단안의 실제표면깊이 센서를 대체하지 않는다.

PC는 색을그리지 않는깊이전처리로 뒤쪽모델을 가린다. 유효한추적/윤곽이없거나 0.5초간 관절프레임이 끊기면 가림을 해제한다.1.5초간 영상이없으면 기존대로 영상정합모델도 숨긴다. 잘못된마스크·보정변경·폰교체/연결종료 때도 이전가림을 남기지 않는다. 실제폰의분할윤곽·머리/옷/빠른동작/추가추론부하·실제깊이오차는 미검증이며 이 기능의완료는 합성픽셀검사 범위다. PC체크해제는 표시만끄며 폰의분할추론 설정을바꾸지 않는다.

**구역 선택(3대)·건물 선택(1대):** 서버 재시작 후 3대는 `/test/building/?key=<접속키>`를 열면 첫 구역이 자동으로 나타나고 ‘시험 구역’에서 다른 구역(건물 2~3개)을 고른다. 1대(`?mode=mono`)는 한 번에 건물 하나만 세우고 ‘건물 선택’에서 IT1 또는 조건에 맞는 건물 61개 중 하나를 고른다. 1대의 ‘건물을 부수면 자동으로 다음 건물’을 켜면 부서진 파편이 설정 비율(기본70%) 이상일 때 설정한 초(기본3초) 뒤 목록의 다음 건물로 넘어가며(마지막 다음은 처음), 복원·수동 선택·옵션 해제는 대기를 취소한다. **새 건물 무적(2026-11-24, 사용자 요청):** 1대·2대 무대에서 건물이 바뀌면(자동 다음 건물·수동 선택) 서버가 2초(`SPAWN_GUARD_MS`) 동안 손목·발목 타격을 무시한다. 관절 궤적은 계속 갱신해 무적이 끝난 직후 첫 프레임이 예전 위치에서 튀어 들어오는 타격이 되지 않는다. 마우스 시험 타격·복원은 막지 않으며, 상태 `model_test.spawn_guard_ms`(남은 ms)를 PC 자동 다음 건물 상태 줄에 표시한다. 3대 삼각측량 화면은 적용하지 않는다. 단독 건물이 필요한 3대 시험은 `&scene=it1`을 붙인다. 폰 입력 없이도 중앙 3D 보기에서 마우스로 시험할 수 있다. 선택한 구역의 건물들이 함께 나타나며 각 건물의 파편마다 충돌·파괴·물리가 적용된다. 광역 타격은 범위 안 다른 건물도 분리할 수 있으므로 개별 접촉을 보려면 광역 타격·지지 붕괴·충격 추가분리를 끈다.

**절대 크기:** 최초87개 건물의평균 높이0.95m로 정한 **공통 축척0.0629757266484059**를 고정 상수로 유지한다. 필터링 후61개의 평균을 다시0.95m로 맞추지 않으므로 남은 건물 크기는 이전과 같다. 사용자 키·보정·구역 크기에 맞춰 재축소하지 않는다. 건물마다 원본 비율/높이 차이는 유지하므로 개별 건물 또는 각 소구역 평균이 모두0.95m인 것은 아니다. IT1 단독은 이 평균 모집단과 별도다. 모든 소구역은 서버 배율1로 강제하고 크기 슬라이더·숫자·적용 버튼을 잠근다. 배율 명령을 보내도 그룹 크기는 달라지지 않는다.

마커 바닥 위에 건물들을 간격0.25m로 나란히 배치한다. 실제 캠퍼스 거리·지형을 재현하지 않는다. 같은 공통 축척으로 표시/충돌체/물리/질량을 생성하며, 중앙3D 카메라만 전체 건물을 볼 수 있게 뒤로 이동한다. 이 카메라 조정은 영상 정합용 카메라나 건물 크기를 바꾸지 않는다.

구역 변경은 파괴 상태·손목 궤적을 복원하고 X/Y·회전·광역/붕괴/깊이 허용 설정을 유지한다. 소구역 배율은1, IT1 단독 복귀 배율은0.6이다. 같은 서버의 1대 PC 화면들이 구역을 공유한다. 준비 중에는 타격을 막으며 GLB와 충돌체를 다시 읽는다. 첫 로딩은 몇 초 걸릴 수 있다. 파괴 후 다음 건물/구역 자동 진행은 아직 없으며 수동으로 선택한다.

구역 목록·사양은 기존 접속키/쿠키로 보호한 `GET /api/test/building-scenes`와 `GET /api/test/building-scenes/{id}`다. `multi3d_model_scene{scene_id}` 명령은 1대 모드만 허용하며 모델 상태에 `scene_id`가 추가된다. `backend/building_scenes.py`가 표시·충돌체에 동일한 배치와 구역 전체의 고유 파편 ID를 생성한다. 지지 붕괴 그래프는 서로 다른 건물을 연결하지 않는다.

## 광역 강타·거리 제한 (2026-11-11)

- ‘광역 타격 · 건물 전체 날리기’ 기본ON, 반경3m·세기12. 현재0.6배 IT1은 반경 안에 전부 들어가므로 빠른 손목 타격 또는 마우스 클릭으로96개를 분리한다. 손목은 연속 관측의 속도가0.8m/s 이상일 때 광역 적용하며 느린 접촉은 한파편만 분리한다. 속도와 실제 힘은 동일하지 않으며 서버도착시각/추적오차의 영향을 받는다.
- 새 이벤트의 범위 안 동적파편에 주방향 충격량 + 작은 방사성분 + 세기의 최소35% 상향성분을 적용해 건물이 통째로 날아가는 연출을 만든다. 거리에 따라65~100%로 감쇠하고 상한속도를 적용한다. 실제 구조물의 물리적 파괴 예측은 아니다. 광역OFF로 한조각씩 치는 방식과 비교한다.
- ‘충격 범위’는0.1~10m, 세기는1~20(서버0.1~20)을 허용한다. 광역 여부/범위/손목세기는 `multi3d_model_blast_config{enabled,radius,strength}`로 서버 공유한다. 모델 상태에 `blast_enabled`, `blast_radius`, `blast_strength`, 타격 이벤트에 `blast`, `blast_radius`, `strength`가 포함된다.
- ‘파편끼리 충돌 거리’ 기본0.75m(0.05~5m). 동적파편 중심끼리 이 거리보다 멀면 접촉 해결을 생략한다. 바닥·고정건물·손목 충돌은 별도 옵션을 유지한다. Rapier 자체의 공간탐색도 먼 물체를 제외하므로 추가거리필터가 항상 성능향상을 뜻하지는 않는다. 너무 낮으면 큰 파편끼리 접촉해도 관통할 수 있어 표시배율에 맞춰 조정한다.
- 거리필터는 step 전에 캐시한 좌표만 읽는다. 엔진이 step 중일 때 Rust/WASM 물리세계에 재진입하지 않는다. 단순 전체낙하96개/합성4화면에서는 약60FPS·step p95약3.7ms를 확인했으나 강타 순간/실폰/장시간 성능은 별도 측정 대상이다.

1. 서버를 재시작한다(새 서버 판정 모듈 필요).
2. PC에서 `/test/building/?key=<접속키>`를 연다. `/monitor/`와 기존 `/test/multi3d/view.html`에도 링크가 있다.

## 판정과 상태

- 서버 `backend/fragment_test.py`가 IT1 파편96개 볼록 충돌체를 읽는다. 각 손목의 직전→현재 선분이 남아 있는 충돌체에 처음 진입하면 그 파편만 제거한다. 한 프레임에는 전체 손목 중 먼저 닿은 한 개만 처리한다.
- 첫 점·미검출 복구·250ms 넘는 간격·1.5m 넘는 점프는 기준점으로만 사용한다. 몸이 건물과 겹쳐 있을 때(건물 위에 서 있거나 손/발이 이미 파편 안)도 손/발이 **1.5m/s 이상, 프레임 사이 8cm 이상** 빠르게 움직이면 그 손/발이 들어 있는 파편이 깨진다(이벤트 overlap=true, 같은 관절은 300ms에 한 번). 느리거나 떨림 수준이면 겹쳐 있어도 깨지지 않는다(진단: 건물 위에 서 있음/허용 범위 안). 발목은 20cm 이상 들려 있어야 한다. 1대는 위의 근사범위 내 빠른동작 조건을 추가로 쓴다.
- 분리된 충돌체는 서버의 남은 건물 타격 판정에서 제외하며, PC의 Rapier 세계에서 동적 물체가 된다. 움직이는 파편끼리와 고정 건물·바닥·추적 손목의 물리 충돌을 적용한다.
- 추적 손목은 반경5cm의 운동학 구체이며 분리된 파편에만 물리적으로 접촉한다. ‘손목과 부서진 파편 충돌’ 기본ON이며 OFF 가능. 첫 관측·미검출·250ms만료·1.5m점프 후에는 재기준을 잡고, 파편 내부에서 복구되면 밖으로 나올 때까지 충돌을 끈다. 손목 이동은 물리step당12cm로 제한한다. 손목2개가 관측되면 기존97강체에 최대2개가 추가되며 복원 시 정리한다. 실폰 손목 위치 오차와 반경은 실측 조정이 필요하다.
- 여러 뷰어가 서버 하나의 시험 상태를 공유한다. 배치 변경·복원은 모든 뷰어에 반영한다. 재접속 시 누적 제거 목록을 다시 받아 상태를 맞춘다. 저장·60초 게임/점수 연결은 하지 않는다.
- 폰의 기존 상자 표시·타격 횟수와 새 PC의 모델 파편 횟수는 별도다. 모델 정합 영상은 새 PC 화면에서 확인한다.

## 2026-11-11 파편 물리 확장

- 중력9.81m/s², 마찰·반발·각운동, 고정건물/파편/바닥 충돌과 CCD를 Rapier 고정60Hz로 계산한다. 한 표시 프레임에서 최대4번 진행하고 과거 시간 누적을 제한한다. 정지한 물체는 sleep으로 계산을 줄인다.
- 정상 파편은 고정 물체이며 분리된 파편만 동적으로 바꾼다. 복원/배치 변경은 기존 물리 세계를 해제하고 새97강체(파편96+바닥1)로 만든다. 네 화면이 한 물리 세계를 공유한다.
- 타격점에 질량을 고려한 충격량을 적용해 직선/회전 운동을 만든다. 초기 속도 약1.2m/s와 상향 성분은 연출용 설정이며 사용자의 실제 힘을 측정한 값이 아니다.
- 서버는 정지 파편의 서로 마주 보는 면·근접 경계로 접합 그래프를 만들고 바닥에 연결되지 않게 된 부분을 함께 분리한다. 기존 장식물이 처음부터 공중에 있으면 별도 고정점으로 보존한다. 이는 연결성 근사이며 재료 강도·응력·실제 건축물 붕괴 해석이 아니다. 실제 IT1의 바닥 파편21개를 제거하면 나머지75개가 지지를 잃는 합성 검사를 통과한다.
- PC가 8N 이상의 파편→남은 건물 접촉력을 감지하면 서버에 해당 파편의 추가 분리를 요청한다. 150ms 간격·요청당 최대8개로 제한한다. 힘 기준은 게임용 초기값이며 실측 보정 전이다.
- 물리 효과 패널에서 중력·바닥·건물·파편 충돌·회전·sleep·지지 붕괴·충격 추가분리를 각각 끈다. 붕괴 설정·분리 목록은 서버에서 공유하고 나머지 물리 옵션/운동은 각 PC에서 계산한다. 서로 다른 PC의 파편 궤적은 같다고 보장하지 않는다.
- `96개 전체 낙하 · 합성 부하 시험`은 폰 없이 전체 파편을 분리한다. FPS·물리step CPU p95·프레임 CPU·동적/sleep 개수를 표시한다. 물리step CPU가 전체 GPU 렌더 지연은 아니다. 부하가 크면 파편 충돌/추가분리·붕괴부터 끄며 비교하고, sleep은 켜 두는 편이 계산을 줄인다.
- `node --test tests/test_fragment_physics.mjs`는 바닥·중력·동적/고정 충돌·회전잠금·sleep·접촉력·최대step·실제96개 물리 부하를 확인한다. 브라우저 시험은 실GLB+합성입력에서 전효과·반복복원과 표시/판정 일치를 확인한다.

## 통신 추가(계속)

1대 모드는 `/ws/test/mono3d?role=viewer&model=it1`을 구독한다. 기존 폰의 `mono3d_calib/frame/jpeg`를 그대로 받으며 `mono3d_model_state{source:mono_approx,timing:server_arrival,model_test}`를 추가로 받는다. 모델 명령은 아래와 동일한 이름을 재사용한다(소켓이 달라 상태는 분리). 유효/유한 근사관절만 서버접촉에 쓰고 촬영시각동기화나 삼각측량 결과로 바꾸지 않는다. 관측타입의 부재·폰교체·카메라보정변경은 궤적을 초기화한다. 일반프레임상태는 최신것만, 타격이벤트는 신뢰큐로 전달한다. 기존 상자뷰어는 모델명령을 받지 않고 기존 전달을 유지한다.

1대 전용 `multi3d_model_depth_config{margin}`은0~0.5m 유한값을 받으며 궤적을 재기준한다. 3대에서 이 명령은 거부한다. 모델상태의 `depth_margin`, `diagnostics{left_wrist,right_wrist}`는 이유/위치/외곽깊이차이/외곽거리이고, 이벤트 `approx_depth_margin_m`으로 근사허용 여부를 구별한다. 외곽거리0이 정확한 비볼록 메시 접촉을 보장하는 것은 아니다.

기존 `/ws/test/multi3d?role=viewer&model=it1` 구독이 모델 판정을 활성화한다. 키/쿠키 인증은 기존 경로와 같다.

- `multi3d_model_state`: 첫 접속 시 `model_test` 전달.
- 기존 `multi3d_fused`에 `model_test` 추가(비활성은 null). `building_id`, `epoch`, `placement`, `fragment_count`, `removed_ids`, `bounds`, `event`를 포함한다. 이벤트에는 고유 ID·관절·파편 ID·접촉점·이동 방향이 있다. 이벤트 프레임은 최신 교체 큐로 버리지 않으며 누적 제거 목록으로 유실/재접속도 복구한다.
- 뷰어 `multi3d_model_config{placement:{x_m,y_m,yaw_deg,scale}}`: 배치 적용과 복원. X/Y ±5m, 배율0.1~2, 모든 값 유한.
- 뷰어 `multi3d_model_reset`: 전체 복원·epoch 교체·궤적 초기화.
- 뷰어 `multi3d_model_drop_all`: 합성 전체 분리. `multi3d_model_release{ids}`는 파편 충격의 추가 분리 요청(최대8개), `multi3d_model_collapse{enabled}`는 공유 붕괴 설정. 모델 상태에 `collapse`, 이벤트에 `kind`, `released_ids`, `unsupported_ids`가 추가된다.
- `multi3d_model_mouse{origin,direction}`: 중앙3D 카메라의 마커좌표 광선, 서버가 남은 충돌체 중 첫 접촉을 판정한다. 벡터는3개의 유한값·성분절댓값100 이하·방향길이양수로 제한한다. 결과 이벤트는 `kind:mouse`, `input_mode:mouse_demo`다. 폰 보정/좌표가 없어도 동작한다.
- 마우스 요청의 `strength`는0.1~20 범위의 유한값이며 기본12이다. `multi3d_model_push{fragment_id,point_m,direction,strength}`는 이미 분리된 파편만 다시 밀고 파괴 개수는 늘리지 않는다. 결과 `kind:mouse_push`, `input_mode:mouse_demo`는 동일 서버 누적 상태와 함께 전달한다.

## 빌드·검증·한계

`npm run build:building-test`로 `frontend/building-test/`를 `web/test/building/`에 빌드한다. 기존 세 게임 빌드와 별도이며 새 번들도 저장소 공유 대상이다.

- `python -X utf8 -m pytest tests/test_fragment_test.py tests/test_multi3d_relay.py tests/test_model_strike.py -q -p no:cacheprovider`
- `npx playwright test --config playwright.building-test.config.js` (Windows Edge)

검증은 실제 GLB/충돌체 + 합성 카메라 관측·합성 JPEG 영상·합성 손목이다. 실제 폰·사람의 정합 정확도/지연·촬영 시각 동기화·장시간은 미검증이다. JPEG 영상과 손목은 별도 전달되므로 움직이는 손과 겹침에 시간차가 있다. 실제 측정 후 허용 오차·배율·장비 배치를 조정해야 한다.

## 2026-11-16 사람 3D 표시·사람 앞 가림

마커 기준 3D 화면은 관측한 코·어깨·팔꿈치·손목·골반·무릎·발목을 사용해 머리·몸통·팔다리를 그린다. 실제 사람 스캔/사진 텍스처가 아닌 관절 기반 사람 모형이다. 없는 관절은 만들지 않고 해당 부위를 숨긴다. 입력 만료(500ms)·연결 종료·보정 변경 시 남은 모형을 정리한다. 건물의 초기허리70% 고정·물리/점수는 그대로다.

PC 영상의 사람 뒤 가림은 기본 ON이다. MediaPipe 사람분할 윤곽과 관절의 카메라Z 깊이를 결합한 깊이 전처리로 뒤쪽 모델만 가리며 앞쪽 모델·윤곽 밖은 보존한다. PC는 동적 파편도 가린다. 깊이는 같은 JPEG에 깊이PNG로 동봉한다.

3대 폰도 기존 Pose의 분할 출력을 켜며 추가 추론 모델은 쓰지 않는다. 최근 융합 결과가 200ms 이내이고 네 몸통 관절이 필수로 있고 보이는 관절들이 현재 랜드마크와 재투영 오차 max(12px,영상대각2.5%) 안에서 맞을 때만 그 깊이를 사용한다. 서버가 교정한 좌우 라벨 반전도 반영한다. 늦거나 불일치하면 가림을 보류한다. PC에서 카메라 프레임이 순차 도착해 잠깐 1시점만 정렬됐을 때는 200ms 이내 최근 유효 몸통을 유지하고, 유효 2시점 이상에서 추적 무효가 확인되면 즉시 해제한다. 실제 관절 누락은 복원하지 않는다.

사람 표면 깊이는 관절 깊이에서6cm를 보정한 근사이고 실제 깊이 센서가 아니다. 실폰의 가림 경계/빠른 동작/조명/지연·세 폰 추가 부하는 미검증이다. 적용은 build:building-test 후 서버 재시작·PC/폰 새로고침이며, 3대 폰은 분할 출력 옵션을 새로 적용하도록 카메라를 다시 켠다.
