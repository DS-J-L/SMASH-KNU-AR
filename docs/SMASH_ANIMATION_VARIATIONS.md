## 1. 권장 구성과 현재 코드

**첫 구현은 연쇄 폭파·스윙 충격파·압궤 붕괴·중력 압축의 4종을 권장한다.** 같은 전체 파괴/점수 규칙에서 바깥으로 폭발·타격 방향으로 밀림·빠르게 내려앉음·안쪽으로 짧게 수축하는 차이를 만든다. 상승 분출·전격 분해는 확장으로 둔다. ‘실제 힘을 정확히 재현함’보다 슈퍼 모드의 큰 파괴감·접촉 인과·짧은 리듬을 우선하는 설계 판단이다.

| 연출 | 주된 움직임 | 구별되는 장면 | 음향 제안 | 시각 연출 길이 제안 |

구현 전 기준 bf7902c의 코드 경계는 다음과 같다. 이후 실제 변경은10절을 따른다.

첫 적용 대상은 기존 3대 연쇄 폭파다. 일반/2대 무대의 표시 재사용은 후속 선택 사항이며, 이 설계로 그 경로에 전체 파괴 규칙을 적용하지 않는다.

## 2. 기본 4종 상세

### A. 연쇄 폭파 — 익숙한 기본 타격감

- 0~80ms: 실제 접촉점에 작은 고온 중심과 짧은 파편 튐. 먼 화면까지 한 번에 하얗게 채우지 않는다.
- 80~300ms: 불규칙 화염과 타원 고리가 현재 장면의 넓이까지 자란다. 맞은 조각을0ms 첫 그룹에 넣고 거리 정규화 순으로 방출한다.
- 300~900ms: 방사 방향과 실제 타격 방향을 섞은 큰 조각, 가까운 건물부터 전파되는 폭발이 주인공이다.
- 900~2100ms: 불은 사라지고 먼지/작은 잔해가 남는다. 사람·배경이 다시 잘 보이게 정리한다.
- 구현: 기존 자산과 코드를 가장 많이 재사용한다. 매 타격마다 전체 길이를 바꾸기보다 중심 비대칭·불꽃 각도·몇 개의 잔해 충돌 시점을 event seed로 조금 달리한다.
- 차별 기준: 무음에서도 접촉점에서 외향으로 퍼지는 원형 실루엣이 읽혀야 한다.

### B. 스윙 충격파 — 한 방이 장면을 쓸어내는 손맛

- 0~60ms: 접촉점의 짧은 타격 섬광과 첫 저역 충격. 소리도 스윙음부터 기다리지 않고 접촉 때 시작한다.
- 60~250ms: 서버 이벤트의 direction을 같은 C0 카메라로 투영해 넓은 충격 띠를 뻗는다.
- 80~700ms: 띠가 지나간 순서대로 파편이 타격 방향으로 밀린다. 오른손/왼손을 이름으로 구별하지 않고 실제 direction을 쓴다.
- 700~1700ms: 궤적이 사라지고 건조한 잔해·먼지가 남는다.
- 구현: 기존 파편을 쓰며 새로운 절단면을 만들지 않는다. 화면 안쪽으로 향한 벡터가 짧게 투영되면 **정면 충격 고리와 원근 속도선**을 사용한다. 실제와 무관한 가로 방향을 만들어내지 않는다. 중력은 유지하되 방향 성분이 방사 성분보다 우세하게 한다.
- 차별 기준: 같은 색/접촉점에서도 방향이 있는 넓은 띠와 이동이 보여야 한다. 무기/검이 추가된 것으로 보이는 가느다란 절단선은 피한다.

### C. 압궤 붕괴 — 무게감과 건물 스케일

- 0~80ms: 맞은 조각의 작은 깨짐과 강한 접촉 충격. 하단의 먼지부터 느리게 기다리지 않는다.
- 80~300ms: 위→아래 압력선/압축 고리와 하층 해제를 함께 시작한다. 낮은 건물도 하향 인상을 읽도록 보강한다.
- 200~950ms: 건물별 정규화 높이의3~4그룹을 짧게 해제해 큰 실루엣이 급격히 내려앉는다. 파편을 위로 쏘지 않는다.
- 950~2000ms: 바닥 먼지와 낮은 잔해로 정리. 실제 동적 잔해의 정리는 공통4초 이내다.
- 구현: ‘층’은 실제 층수/구조해석이 아니라 높이 그룹의 연출이다. 여러 건물 장면은 building_id별 높이로 그룹을 만들고 같은 이벤트 안에서 진행한다. 기존 processSuper의2.3m/s 상승 하한을 이 프리셋에 적용하지 않는 실제 분기가 필요하다. Rapier가 인수한 조각에는 수동 위치 곡선을 동시에 적용하지 않는다.
- 차별 기준: 한 방에 외향으로 날리는 장면보다, 건물 높이가 줄어드는 과정과 세 차례의 낮은 충격음이 읽혀야 한다.

### D. 중력 압축 — 슈퍼 모드의 짧고 강한 초현실적 마무리

- 0~80ms: 타격점의 짧은 충격과 핵 생성. 흡입 준비를 오랫동안 기다리지 않는다.
- 80~300ms: 넓은 장면의 가까운 파편부터 안쪽 회전이 시작된다.
- 200~1000ms: 큰 실루엣이 접촉 핵으로 급격히 감기고 작아진다. 색 변화만이 아니라 실제 파편의 화면 궤적이 바뀌어야 한다.
- 1000~2100ms: 핵이 닫히고 잔광/공명만 감쇠한다. 다시 큰 외향 폭발을 붙이지 않는다.
- 구현: 슈퍼 모드에서 채택 가능한 초능력 표현이다. 이 프리셋의 조각은 **시각 전용 소유자**를 사용하고 동적 충돌체는 꺼 둔다. 같은 조각에 Rapier 동적 몸체 해제와 수동 transform을 둘 다 적용하지 않는다. 기본 바닥 잔해 대신 압축 소멸을 결과로 삼는다는 차이를 사용자 비교에서 따로 확인한다.
- 차별 기준: 파편이 멀어지는 대신 가까워지고, 끝날 때 바닥 잔해보다 빈 공간이 남아야 한다.

## 3. 확장 2종

### E. 상승 분출 — 발차기와 어울리는 수직 리듬

0~80ms 접촉점 반응 → 80~300ms 바닥 고리 → 150~850ms 하층부터 위로 솟음 → 850~2200ms 낙하·착지음. 압궤와 반대의 실루엣이다. 접촉점 반응을 먼저 보여 주고 지면 변형·새 충돌체·카메라 이동은 하지 않는다. 수직 추가 이동의 초기 목표 상한은 **건물별 높이 H의0.28배**다. 실제 물리에서는 중력 g와 Δh로 v_z≤sqrt(2gΔh)를 초기값으로 산정하고 감쇠/충돌은 따로 시험한다. 기존 무조건2.3m/s 상승을 그대로 쓰면 작은 건물의 이 상한을 보장할 수 없다. 시안의 높이 비례 시간 곡선은 실제 Rapier 중력 계산이 아니다.

### F. 전격 분해 — 면에서 선·입자로 바뀌는 질감

0~80ms 접촉점 작은 전기 고리 → 80~500ms 표면을 따라3~5개의 균열 가지 → 300~1000ms 그룹별 분해 → 1000~1800ms 가벼운 입자 잔향. 균열 끝점은 안정적인 fragment_id로 선택해 **움직이는 조각의 현재 transform**에 붙인다. rest 위치에 번개만 남기거나 정렬 순서가 바뀔 때 연결 대상을 바꾸지 않는다. 연속 화면 점멸 없이 선을 밝히고 감쇠시킨다. 새 조각 수백 개보다 기존 메시 그룹과 소수 입자를 쓴다. 번개는 시각선이며 새 판정/재타격이 아니다.

## 4. 공통 타임라인·선택 경험

시간의 기준은 **PC가 유효한 서버 이벤트를 받아들인 순간 t0**다. 카메라·추론·서버 판정·실영상 재생은 계속 흐른다. 모든 기본 스타일은0~80ms 접촉 반응, 대략100~950ms 큰 장면 변화, 이후 잔해/잔광 정리를 목표로 한다. 효과 길이가 타격 반응 지연이 되어서는 안 된다. 기존 첫 draw100ms 초과 취소를 유지하며 이는 새 시안에서 실제 카메라 지연을 측정했다는 뜻이 아니다.

- 설정 이름: `파괴 모드`와 별도의 **연출 스타일**. 선택지는 4종 또는 6종의 이름과 `섞어서 재생`이다.
- 운영자가 복원/준비 단계에서 고른다. armed 상태에서 바꾼 선택은 다음 라운드에 적용해 진행 중 이벤트의 소리/물리 스타일이 섞이지 않게 한다.
- 기본값은 기존 연쇄 폭파다. 최초에는 설정한 스타일을 고정해 비교하기 쉽게 하고, 취향을 확인한 뒤 섞어서 재생을 쓴다.
- 섞기는 허용된 프리셋을 한 번씩 사용하는 덱으로 처리한다. 덱 경계에서도 직전과 같은 스타일을 피한다. 방출 각도·먼지/소리의 작은 차이는 같은 프리셋 안의 seed 변형이다.
- 무득점 미리보기는 본 파괴 없이 화면/음향/시각 전용 파편만 보여 준다. 실제 장비 준비·점수·제거 집합을 바꾸지 않는다.
- 프리셋마다 별도 버튼/단축 제스처를 요구하지 않는다. 유효한 한 번의 타격에 선택한 연출 한 개만 재생한다.

## 5. 코드·계약 구조 제안

공통 수명 관리와 검증은 한 곳에 두고 각 프리셋은 화면·파편·음향의 묶음으로 정의한다. 아래는 v0.2의 구조 제안이다. v0.3의 실제 파일/공개 데이터·차이는10절을 따른다. screenPlan/fragmentPlan/audioPlan 같은 개념 이름을 실제 API로 간주하지 않는다.

~~~text
feedback-presets.js
  id → durationMs, screenPlan, fragmentPlan, audioPlan, reducedPlan

유효 이벤트 → 기존 instance/epoch/revision/중복/표시 검사
           → 이번 이벤트의 preset/seed를 한 번 확정
           → 화면 + 파편 + 소리를 같은 t0로 시작
취소 신호  → 세 채널의 예약·몸체/시각 프록시·오디오를 함께 정리
~~~

주요 작업 지점:

| 위치 | 제안 변경 |
| --- | --- |
| `super-smash-feedback.js` | 기존 검사와 취소를 유지하고 preset/seed/t0 한 번 확정, 화면·물리·음향에 같은 계획 전달 |
| `screen-impact.js` | 현재 연쇄 폭파 보존, 고정 IMPACT_DURATION_MS 대신 프리셋별 duration 사용·100ms 첫 draw 제한은 유지 |
| `fragment-physics.js` | 방출 시각·초기 속도/시각 궤적과 상향 하한을 프리셋별로 분리. 폭파/스윙/압궤/상승은 제한된 동적 물리, 압축/전격은 시각 전용 소유자 |
| `impact-audio.js` | preset별 합성 음색·큐 간격, 공통 unlock/mute/cancel과 동시 source 예산 유지 |
| `main.js`/운영 설정 | 스타일/미리보기 표시, 공통 t0와 취소 연결; 일반·duo 경로와 중복 재생 차단 |
| 서버 이벤트/선택 제어 | 이후 실제 구현 범위에서 프리셋 allowlist·고정 선택/섞기·이벤트 결정값 확정 |

서버 필드의 호환 가능한 추가 예:

~~~json
{
  "effect_style": "screen_impact_v1",
  "feedback_preset": "gravity_compress_v1",
  "feedback_version": 1,
  "feedback_seed": 381204
}
~~~

기존 `effect_style`을 새 프리셋 이름으로 바로 교체하면 현재 어댑터가 효과를 거부한다. 기존 값과 파괴/점수/접촉/관절/출처 필드를 유지하고 선택 필드를 점진 도입한다. **같은 프리셋 버전·에셋을 지원하는 PC끼리** 서버가 고정한 preset/seed로 재현한다. 알 수 없는 preset/version·없는 필드는 연쇄 폭파로 대체하고 requested/played preset을 기록한다. 구형 PC도 새 스타일을 동일하게 재생한다고 약속하지 않는다. 운영 PC는 화면·파편·음향 준비/지원 버전을 확인한 뒤 기존 presentation_ready를 보낼 수 있어야 한다. 실제 도입 시 [데이터 계약](DATA_CONTRACT.md)과 관련 담당 계획을 갱신한다.

서버 변경 전 첫 시제품에서는 `event_id`와 고정 프리셋의 해시로 seed를 만들 수 있다. 이 경우 PC별 설정이 달라질 수 있다는 한계를 기록한다. 저장된 이벤트 replay의 시각 재현과 네트워크 reconnect snapshot은 구별한다. 후자는 현재처럼 소리를 포함해 재연출하지 않는다.

## 6. 파편 계획·좌표·공통 한도

파편 중심·접촉점·방향은 marker 미터 좌표, z-up에서 계산한다. Three 표시 변환은 기존 경로에서 한 번만 적용한다. 화면 효과만 올리려고 실제 보정 K/R/t·건물 배치·판정 좌표를 이동하지 않는다. 한 프리셋 안에서도 실제로 맞은 파편의 시각 반응은 첫 그룹에 포함한다.

| 연출 | 방출 순서 제안 | 주요 이동/표시 |
| --- | --- | --- |
| 폭파 | 접촉점 거리순0~650ms | 접촉점 반대 방사 + 타격 방향 + 위 성분 |
| 스윙 | 실제 접촉 조각0ms·방향 띠40~340ms | 실제 direction 우세, 화면 안쪽이면 정면 고리/원근 표현 |
| 압궤 | 실제 접촉 조각0ms·건물별 하층→상층60~420ms | 상승 하한 없음, 중력 하향·작은 안쪽 성분·낮은 잔해 |
| 압축 | 실제 접촉 조각0ms·거리순0~140ms 진입 | 약0.82초 압축 곡선·회전 반경 축소, 시각 전용 |
| 상승 | 하층→상층80~500ms | 제한된 수직 초기 속도와 중력 낙하 |
| 전격 | 결정된 균열 그룹80~600ms | 작은 튐·그룹별 감쇠·소수 입자 대체 |

기존 동적 몸체128개·프레임당16개 및3ms·선속도24m/s·각속도25rad/s·4초 정리 경계는 유지한다. 흡입의 시각 프록시와 전격 입자는 별도 pool을 쓰되, 첫 시제품에서 각각64개/96개 이내의 **상한 제안**으로 시작한다. 두 표현으로 동일 메시를 이중 표시하지 않는다. 같은 이벤트에서 프리셋을 겹쳐 합산하지 않는다. 화면 Canvas의 DPR1.5/긴 변1920px 기존 상한도 유지한다.

음향은 프리셋마다 음색과 발음 간격을 바꾸되 단일 PC 소유자와 기존 총14 source 이하의 예산을 공유한다. 큰 음량을 차별점으로 쓰지 않는다. 성능이 부족하면 장식·동적 대표 파편 수·해상도 순으로 줄이고, 점수/제거 집합은 모두 적용한다. 강제 대체가 발생하면 진단에 requested/played preset을 남긴다.

복원·장면/epoch/instance 변경·일시중지·탭 숨김·표시 상실·단절에서 큐·시각 프록시·오디오 예약을 즉시 취소한다. 음소거는 소리만, 동작 줄이기는 짧은 접촉 잔광과 정적 결과로 처리한다. 중지는 서버 판정 중지와 로컬 연출 취소를 기존 의미대로 구별한다.

## 7. 구현 순서와 검증

1. **공통 프리셋 골격 + 기존 폭파 이관.** 현재 기본 효과가 바뀌지 않게 먼저 회귀하고, 무득점 화면 비교·취소/중복 검사를 만든다.
2. **스윙 충격파.** 이벤트 direction·좌/우/화면 안쪽 투영, 현재 메시 재사용과 넓은 충격 띠를 연결한다.
3. **압궤 붕괴.** 상향 하한 분리·건물별 높이 그룹·즉시 파쇄/압력선·짧은3단 음향을 연결한다.
4. **중력 압축.** 시각 전용 경로로 기본4종을 완성한다. 같은 메시/ID의 동적 몸체와 수동 transform 중복을 검사한다.
5. **선택/섞기와 서버 결정값.** 이벤트별 preset·seed/하위 호환·운영 PC 변경·재접속을 연결한다.
6. **상승·전격 확장과 실제 장비 인수.** 기본4종의 프레임 비용·정합/청취 결과를 보고 추가한다. 기존 3대 인수는 별도로 계속 남는다.

기존 역할을 유지한 제안 분담: 이동수는 화면/스타일 선택·C0 정합과 조합, 김태이는 파편 궤적/음향·단일 재생과 예산, 정경호는 필요한 이벤트 필드·동기화/재생 로그를 맡는다. 새 담당 확정이나 착수·납기 합의가 아니다. 이번에는 구현 체크리스트를 완료 처리하지 않는다.

인수할 항목:

- 실제 IT1·본관·여러 건물 장면에서 같은 접촉점/카메라/seed로 기본4종을0/80/300/600/950ms에 비교한다. 같은 색/무음의 궤적 구별과 실제 소리 포함 비교를 나눠 확인한다.
- 좌→우·우→좌·화면 안쪽·아래→위 이벤트에서 방향/첫 접촉이 맞는지 확인한다. 작은 투영 벡터를 임의 가로 방향으로 바꾸지 않는다.
- 압궤가 위로 솟지 않는지, 압축에 동적 충돌체가 남지 않는지, 전격 연결선이 현재 파편을 따라가는지 확인한다. 상승 추가 높이는 건물별 목표와 비교한다.
- 모든 스타일에 똑같은 입력을 재생해 제거 ID 집합·점수·수락/거부 결과가 기존과 같음을 비교한다.
- 실제 타격점이 모든 스타일의 첫 반응점인지, 화면 크기/회전 변경에서도 정합이 맞는지 확인한다.
- 중복/역순/재접속 snapshot·복원 도중·카메라 상실·운영 PC 교체에서 과거 화면/소리가 재생되지 않아야 한다.
- 일반/mono/duo의 기존 판정·파괴 범위를 유지하고, duo의 한 swing에 효과/음향 한 번이 유지되는지 확인한다.
- first draw·스크린/물리/소리 개별 비용·frame p95·정리 후 몸체/메모리·일반 baseline 대비 추가 비용을 측정한다. 이번 시안 결과를 실제 장비 지연/성능으로 쓰지 않는다.
- 20분 반복과 음소거·동작 줄이기·저사양 대체를 실제 PC/폰에서 확인한다. 실제 청취/음량 조정 후 음색을 확정한다.

## 8. v0.2 검토 시점의 결과와 남은 일

v0.1 결과물은6종 설계와 동일 블록의 무음 시안이었다. v0.2는 **슈퍼 모드만** 대상으로 실제 IT1/본관 충돌체의 외곽·배치/비율을 읽어 만든6종 무음 시안으로 교체했다. **v0.2 시점에는** 실제 GLB 재질/표면·C0 영상·서버 이벤트·Rapier/WebAudio를 연결하지 않았고 제품 JS/서버/번들/데이터 계약·계획 체크리스트도 바꾸지 않았다. 이 과거 검수와10절의 실제 구현 검증을 구분한다.

v0.1 검수 이력: Edge headless6종·7488개 유한 표본·모바일/축소 동작 통과. 이 결과를 적합성 검증으로 확대하지 않는다. v0.2 검수: 2개 실제 파편 데이터×4방향×6종=48조합, 총108600개 시점/파편 표본에서 유한성·초기 형상 보존·첫 접촉 조각의 방출 예약 지연0ms·압궤 비상승·상승 추가 높이≤0.28H를 확인했다. 시안의 좌/우/깊이 스윙의 방향 성분 양수와 고정 투영의 정면 방향 길이0도 두 건물에서 확인했다. 기본4종을 같은 회색·무음·80/300/750ms에 맞춘12프레임으로 시각 검토해 외향 고리/방향 띠/하향 압력/내향 수축의 차이를 확인했다. 이는 한 검토자의 시각 판단이며 참가자 분류/선호 시험이 아니다. 브라우저 선택/재생/일시정지/시간 이동·축소 동작·모바일 가로 넘침·오류0도 검수했다. 실제 C0의 K/R/t 투영·카메라/서버 지연을 확인한 결과로 사용하지 않는다.

남은 적합성 확인은 같은 실제 C0/건물·한 방 입력에서 기본4종을 순서 섞어 체험하고 타격 위치/방향 이해·통쾌함·다음 시도 방해 여부를 비교하는 것이다. 첫 사용 스타일과 순서를 바꿔 편향을 줄이고 선호/이유를 원자료로 기록한다. 그 결과와 청취·정합/성능 확인 전에는 적합성 확정/공통 Phase 완료로 표시하지 않는다. 다음 구현은7절의 프리셋 골격·기존 폭파 이관이다.

## 9. 변경 이력

- v0.1: 연쇄 폭파/방향 절단/압궤 붕괴/와류 흡입 기본4종과 상승/전격 확장2종, 동일 블록 시안. 실제 형태·방향·기존 상향 속도 분기 검증이 부족했다.
