# 판정 폰 2대 + 화면 폰 시험 (2대 무대)

2026-11-17 사용자 결정: 판정 폰 2대를 높이 0.66m, 2m 간격으로 일직선에 두고 A3 마커 2장으로 [넓은 무대](WIDE_STAGE_TEST.md)와 같은 방식(폰별 1대 근사 깊이, 마커 간격만큼 좌표 이동)으로 사람 위치를 계산한다. 반대편 1.6m 높이에 **화면 폰**을 가로로 두고 두 마커를 한 번에 인식해, 그 영상에 건물을 합성한 화면을 메인 화면으로 쓴다. 화면 폰은 판정하지 않는다. 결과는 `source: mono_approx`이며 삼각측량이 아니다. 기존 넓은 무대(`?mode=wide`)·1대·3대 삼각측량 경로는 그대로 둔다.

## 배치

```
                 화면 폰 V (높이 1.6m, 가로, 두 마커가 모두 보이게)
                              ▼
        ┌──────────── 건물 줄 (마커 위·사이) ────────────┐
     ID0 A3 마커  x = -간격/2          ID1 A3 마커  x = +간격/2      ← 무늬 위쪽(+Y)이 판정 폰에서 먼 쪽
          ▲                                   ▲
        C0 폰 (높이 실측)                   C1 폰 (높이 실측)       ← 각자 자기 마커 앞에 고정
```

- 마커: `assets/markers/duo-marker-id0-a3.pdf`, `duo-marker-id1-a3.pdf`를 A3 실제 크기 100%로 인쇄한다(기존 `floor-direction-id0-a3.pdf`는 검은 사각형 200mm의 화살표 도안이라 다르다). 검은 사각형 한 변이 **270mm**인지 잰다. 폰 페이지의 마커 한 변 기본값은 27cm다. 실측값이 다르면 세 폰 모두 고친다.
- 두 마커를 왼쪽부터 ID0·ID1 순서로, **같은 방향**으로 놓는다. 간격(중심 사이)은 정해져 있지 않다(0.5~3m, 2026-11-20 변경). PC의 **화면 폰 실측 간격 자동 적용**이 켜져 있으면(기본) 화면 폰이 두 마커로 잰 간격을 서버가 그대로 무대 간격으로 쓴다. 끄면 줄자로 잰 간격을 PC에 넣는다. 화면 폰 쪽에서 보면 마커가 거꾸로 보이지만, 무늬로 방향을 읽으므로 돌려 놓지 않는다.
- 판정 폰 C0·C1은 자기 마커 앞에 둔다. **높이 두고 아래로 기울여 내려다봐도 된다**(2026-11-20). **2026-11-22 변경(사용자 결정): 0.66m 고정·기본값을 없앴다.** 판정 폰 페이지의 폰 높이 칸은 비어 있고, 바닥~렌즈 높이를 줄자로 재서 넣어야(0.1~3m) 마커 인식·모서리 찍기가 시작된다. 입력한 높이로 화각을 정하고, 마커로 폰의 위치와 각도(기울기·방향)를 계산한다. 저장된 보정을 쓰면 그때 넣은 높이를 그대로 쓴다. 화면 폰 V는 반대편 1.6m 높이에 가로로 두고 두 마커와 무대가 한 화면에 들어오게 한다. 1배 렌즈를 쓴다(초광각은 가장자리가 휘어 건물이 어긋난다).

## 실행

1. 서버를 재시작한다. 새 경로 `/ws/test/duo3d`를 추가했다.
   - 메인 페이지(`/monitor/`) 맨 아래 **폰으로 입장**(`/test/duo/`: 판정 폰 C0·C1·화면 폰 V 중 역할 선택, 주소의 접속 키를 이어 붙임)과 **PC로 입장**(`/test/building/?mode=duo`) 버튼으로도 들어갈 수 있다.
2. PC: `https://<PC 주소>:8443/test/building/?mode=duo&key=<접속키>`. 오른쪽 **마커 간격**에 실측값(기본 2m)을 넣고 **간격 적용**.
3. 판정 폰 2대: `/test/mono3d/?stage=duo&camera=C0&key=<접속키>`, `camera=C1`. 카메라 → 고정 → 마커 자동 인식(자기 번호만) → 몸 보정(자기 마커 중심에서 직립) → 측정.
4. 화면 폰: `/test/stage-view/?key=<접속키>`. 가로로 고정 → **카메라 시작** → 빈 무대에서 **두 마커 인식**. 원본 해상도로 ID0·ID1을 찾고, 약 1초 동안 움직임이 없으면 꼭짓점 8개로 위치를 계산한다. 화면에 파란 선(무대 x축)과 분홍 기둥(각 마커 위 1m)이 실제 바닥·마커와 맞는지 본다.
5. PC 위쪽 큰 화면이 화면 폰 영상(V)이고, 그 아래 작게 C0·C1이 보인다. 사람이 있는 구간의 판정 폰이 판정한다(`★판정`).

## 계산 방식

- **판정:** 넓은 무대와 같다. 마커 n은 x = (n − 0.5) × 간격, 판정 폰 좌표를 그만큼 옮기고, 사람에게 가까운 마커의 폰이 판정한다(0.15m 전환 여유·전환 시 궤적 끊기·가려진 손목/발목은 옆 폰 값 대체). 몸 보정은 판정 폰마다 한다(깊이 추정용이며 건물 크기는 바꾸지 않는다).
- **화면 폰 자세:** 각 마커의 무늬 방향대로 정렬한 꼭짓점 4개 × 2 = 8점과, 서버가 알려준 마커 위치(±간격/2)로 평면 호모그래피(최소제곱)를 구한 뒤 재투영 오차를 최소화한다. 화각은 판정 폰과 같이 **폰 높이(1.6m)로 계산**한다(직접 입력도 가능). 모서리 오차가 720px당 3px를 넘으면 거부하고 "마커 간격·방향 확인"을 안내한다. 입력한 간격이 실제와 다르면 여기서 걸린다.
- **간격 변경:** PC에서 간격을 바꾸면 서버가 화면 폰 자세를 지우고(`multi3d_phone_left{camera_id:'V',reason:'spacing_changed'}`) 새 마커 위치를 보내며, 화면 폰은 저장된 꼭짓점으로 자동 재계산해 다시 보낸다. 다른 간격으로 계산한 자세는 `spacing_mismatch`로 거부한다. 화면 폰은 이 거부를 받으면 오류에 담긴 서버 간격으로 마커 위치(±간격/2)를 새로 만들어 다시 계산한다(2026-11-18 수정: 예전에는 간격 값만 바꾸고 옛 마커 위치로 계산해, 메시지 순서가 바뀌면 틀린 자세가 통과할 수 있었다). 상태 메시지는 간격뿐 아니라 마커 위치가 달라져도 다시 계산한다.
- **마커 배치 실측(2026-11-18):** 판정 폰은 자기 마커 기준 좌표를 간격만큼 옆으로 옮기기만 하므로, 마커가 돌아가 있으면 그 폰의 좌표도 같이 돌아간다(마커에서 d만큼 떨어진 곳은 옆으로 약 d·tan(회전), 1.5m에서 2°면 약 5cm). 건물은 화면 폰이 두 마커로 맞추므로 화면에서는 티가 나지 않는다. 또 기존 8점 검사는 1280×720에서 ID1이 5cm 멀고 3cm 앞으로 나와 3° 돌아간 배치도 통과시킨다(합성 시험). 그래서 화면 폰은 같은 8점으로 **ID1의 위치·회전을 미지수로 함께 풀어** 실제 간격과 두 마커 중심선 기준 회전을 잰다(마커 한 변을 알기 때문에 잴 수 있다). 강체 보정이 실패해도 잰다.
  - 화면 폰 패널과 PC 상태 줄에 `실측 간격 …m(입력 …m) · 회전 ID0 …° ID1 …°`와 `1.5m 앞 옆 어긋남 약 n cm`을 보여 준다. 간격 차이가 3cm를 넘거나 회전이 2°를 넘으면 ⚠로 표시한다. 회전 부호는 위에서 볼 때 반시계가 +다.
  - PC의 **화면 폰 실측 간격 적용** 버튼은 실측 간격을 마커 간격 칸에 넣고 적용한다(입력과 5mm 이상 다를 때만 보임). 그러면 화면 폰이 새 간격으로 자세를 다시 계산한다. 마커 간격 칸은 1mm 단위로 바꿨다.
  - 회전은 **알려 주기만 하고 자동으로 고치지 않는다.** ⚠가 나오면 마커를 두 마커 중심선(바닥 테이프 기준선)에 맞게 돌려 놓고 화면 폰에서 다시 인식한다. 판정 좌표를 회전까지 고치는 자동 보정(서버가 판정 폰별로 회전+이동 적용)은 실측 회전 오차를 실폰에서 확인한 뒤 결정한다.
  - **2026-11-22 변경(사용자 요청): 판정 좌표 자동 보정.** 위 문장은 이전 결정이며 다음으로 바뀌었다.
    - 화면 폰은 자유 배치 풀이(ID1 위치·회전도 미지수)가 성공하면 그 자세를 **두 마커 중심을 잇는 선 기준 좌표**(원점=두 중심의 가운데, x축=중심선)로 바꿔 쓴다. 건물도 이 좌표로 그린다. 강체 8점 풀이는 입력 간격이 바닥과 맞는지 확인하는 검사로만 남는다.
    - 같은 자세로 각 마커의 네 꼭짓점을 바닥에 투영하고 마커 정사각형에 2D 강체로 맞춰 **마커별 바닥 위치·회전**(`marker_poses`)을 구해 `wide3d_view_calib`에 함께 보낸다.
    - 서버는 2대 무대에서 판정 폰 좌표를 무대 좌표로 옮길 때 간격만큼 옮기는 대신 그 마커의 위치·회전을 적용한다(관절, 사람 기준점, PC로 보내는 판정 폰 카메라 자세 모두). 회전 20° 또는 위치 0.3m를 넘는 측정은 잘못 읽은 것으로 보고 쓰지 않는다. 보정 값이 바뀌면 판정 궤적을 끊고 판정 폰 자세를 다시 보낸다.
    - PC의 **화면 폰이 잰 마커 회전·위치로 판정 좌표 보정**(기본 켜짐)으로 끌 수 있다. 상태 줄에 `판정 좌표 보정 켜짐 · C0 회전 … · 위치 …`가 나온다. 끄면 간격만 옮기지만 화면 폰은 여전히 중심선 기준으로 그리므로, 마커가 틀어져 있으면 예전보다 더 어긋날 수 있다.
    - 합성 결과(1280×720, 반대편 3.3m·1.6m, 모서리 잡음 ±0.3px): ID1 5cm·3cm 이동+3°, 두 마커 같은 방향 3°, ID0 −2°·ID1 +2° 세 경우 모두 판정 폰 바닥 점(마커 앞 0.8~1.5m)이 화면 폰 영상의 실제 위치에서 약 0.8px 안에 들어왔다(보정 없이 간격만 옮기면 11~17px). 실폰 정확도는 미검증.
  - 합성 정확도(1280×720·1920×1080, 반대편 3.3m·1.6m, 모서리 잡음 ±0.5~1px): 간격 약 ±1~2cm, 회전 약 ±0.5~1.3°. 잡음이 1px 수준이면 2° 근처에서 경고가 켜졌다 꺼질 수 있다.
- **무대 기본 옵션(2026-11-20, 사용자 결정):** 넓은 무대·2대 무대 PC 화면은 `건물을 부수면 자동으로 다음 건물` 켬, `광역 타격 · 건물 전체 날리기` 끔, 물리 `남은 건물과 충돌` 끔, `지지 상실 붕괴` 끔으로 시작한다. 전체 날리기·붕괴는 서버 무대가 처음 만들어질 때 꺼지고(PC 체크는 서버 상태를 따름, 다음 건물로 넘어가도 유지), 나머지 둘은 PC 페이지 기본값이다. 1대·3대 삼각측량 화면 기본값은 그대로다.
- **새 건물 무적(2026-11-24, 사용자 요청):** 무대 세트가 바뀌면(자동 다음 건물·수동 선택) 서버가 2초 동안 판정 폰 손목·발목 타격을 무시한다. 남은 시간은 `model_test.spawn_guard_ms`. 간격·몸 보정으로 다시 만드는 건물에는 적용하지 않는다.
- **메인 화면 전체화면(2026-11-24, 사용자 요청):** PC의 V 메인 화면 오른쪽 아래 `전체화면` 버튼은 정합된 V 화면만 화면 비율 그대로 가운데에 꽉 채운다(헤더·3D 보기·판정 폰 영상·설정 숨김). 왼쪽 위에 현재 건물의 `무너짐`(부서진 파편 ÷ 전체 파편, %)과 `걸린 시간`(건물이 나타난 때부터, 서버 `model_test.age_ms` 기준이라 새로고침해도 이어짐)을 크게 보여 준다. 무너진 파편이 자동 다음 건물 기준(기본 70%)에 닿으면 시간이 멈추고 `무너뜨림`으로 바뀌며, 새 건물·복원이면 0부터 다시 잰다. 버튼을 다시 누르거나 Esc로 끝낸다. 브라우저가 전체화면을 막아도 페이지 안에서는 같은 화면으로 바뀐다.
- **바닥 파편 사라짐(2026-11-24, 사용자 요청):** 부서진 파편은 바닥에 닿고 2초 뒤 사라진다(화면 표시만, 점수·무너짐 % 그대로). 자세한 규칙은 [BUILDING_FRAGMENT_TEST.md](./BUILDING_FRAGMENT_TEST.md)의 1대 건물 선택 설명.
- **건물(2026-11-20 변경, 사용자 결정): 무대 세트 하나에 건물 하나**, 타격감을 위해 크게. 높이를 캠퍼스 높이 순서대로 **1.0~1.2m**로 맞추고, 바닥 면은 **가로 2.0m × 깊이 1.5m** 안에 들어가야 한다. 너무 긴 축만 따로 눌러 비율을 바꾸되 최대 절반까지만 누르고, 그래도 넘으면 건물 전체를 줄인다. 결과 높이가 0.6m보다 낮은 아주 납작하고 긴 건물 5개는 뺀다 → 61개 중 **56개, 56세트**(높이 중간값 약 1.0m, 대부분 가로 2.0m·깊이 1.5m). 건물은 무대 가운데(x=0)에 놓인다. 무대 폭(간격×구간 수)이 건물보다 좁으면 건물 전체를 줄인다(`fit_scale`). 파편 꼭짓점·충돌체·화면 배율이 축별 `[가로, 높이, 깊이]` 배율을 같이 쓴다(모델 노드에 회전이 없어 비틀림 없음). 아래 11-18 규칙(폭 0.7~0.8m, 세트당 2~3개)은 대체됐다.
- **건물(2026-11-18 변경):** 넓은 무대와 같은 무대 세트 규칙이고, 무대 폭은 간격×2다(건물마다 가로 0.7~0.8m, 축소 없이 들어가는 만큼). 높이 하한 0.5m(비율 유지로 키움)와 1.5m 넘는 건물 제외도 같다. 기본 간격 2m(폭 4m)에서는 30개 건물이 2~3개씩 12세트로 묶이고, 세트마다 가운데 정렬로 놓인다. 장면 id는 `duo:<세트 id>:<간격mm>:<호환용 높이>`.
- **사람 가림(메인 화면, 2026-11-18):** 화면 폰이 자기 영상(PC로 보내는 960px JPEG와 같은 프레임)에서 MediaPipe 자세+분할로 **실제 사람 윤곽**(최대 384×384)을 따고, 윤곽 픽셀마다 근사 깊이를 붙여 JPEG와 함께 보낸다(`camera_z_mm_rg16_alpha_v1`). PC는 이 깊이를 먼저 깔아 사람 뒤 건물만 지우므로, 영상 속 실제 사람이 건물 앞에 그대로 보이고 사람 뒤 건물은 사람에게 가려진다. 화면 폰은 몸 보정을 하지 않는다.
  - 깊이 1순위(`judge`): 서버가 판정 폰의 무대 좌표 관절(`duo_person`)을 화면 폰에 보낸다(250ms 이내만 사용). 관절 위치는 화면 폰 자신의 2D 관절, 깊이만 판정 폰 값. 화면 폰은 사람의 등 쪽을 보므로 MediaPipe의 좌우 이름이 뒤바뀔 수 있어, 투영 어긋남이 작은 쪽으로 좌우를 맞춘다. 맞춘 뒤에도 판정 관절을 화면 폰에 투영한 평균 어긋남이 **화면 폰 몸통 길이(어깨 중심–엉덩이 중심 픽셀)의 50%(최소 12px)**를 넘으면 판정 관절을 쓰지 않고 2순위로 내려간다(2026-11-18). 판정 폰 근사가 크게 틀렸거나 다른 사람·움직인 마커일 때 틀린 깊이로 가리는 것을 막는다. 화면 폰 상태 줄에 `어긋남 n/한도px` 또는 `바닥 발목 기준 근사 깊이 (판정 관절 어긋남 n px > 한도 px)`가 나온다.
  - 깊이 2순위(`floor`): 판정 관절이 없거나 오래되면 화면 폰 자신의 발목을 바닥(8cm)과 만나게 해 발 위치를 구하고, 그 위치를 지나 화면 폰을 향한 세로 평면 하나로 몸 전체 깊이를 근사한다(몸 두께·팔 앞뒤 깊이 없음).
  - 분할 윤곽이 비거나 몸통과 어긋나면 골격 근사 윤곽을 쓴다(1대 시험과 같은 규칙). 윤곽이 없거나 깊이를 못 구하면 PC는 예전처럼 판정 관절 막대(깊이만)로 대신 가린다.
  - 전송 주기(2026-11-18): 화면 폰은 영상을 자주(기본 초당 15장), 윤곽은 드물게(기본 초당 8장) 보낸다. 사람 인식은 윤곽 장에서만 돌린다. 영상만 있는 장은 `occlusion_keep:true`를 보내고, 서버가 마지막 윤곽을 다시 붙여 PC로 보낸다(`occlusion_t_ms`=윤곽 장 시각). 그래서 윤곽 장이 중간에 버려져도 PC가 놓치지 않는다. PC는 같은 윤곽이면 다시 불러오지 않고, 윤곽 나이는 윤곽 장 도착 시각부터 잰다(500ms 넘으면 끔). 빠르게 움직이면 가림이 최대 윤곽 간격만큼 늦게 따라온다. 화면 폰 패널에서 영상 8~30장/초, 윤곽 4~15장/초를 고르고, 실제 장/초·한 장 처리 시간·전송 Mbps를 1초마다 보여 준다.
  - PC 상태 줄: `V 실제 사람 윤곽 가림 · 근사 깊이` / `V 윤곽 없음 · 판정 관절 막대로 대신 가림`. 화면 폰 패널의 `실제 사람 윤곽으로 건물 가림`으로 끄고, lite/full 모델을 고른다.
- **영상(2026-11-20 WebRTC 추가):** 화면 폰 패널의 **PC로 영상 보내는 방식** 기본값은 `WebRTC 직접(같은 와이파이)`다.
  - PC가 받기 전용 연결을 제안(offer)하고 화면 폰이 카메라 트랙으로 응답한다. 서버는 `rtc_signal`(offer/answer/ICE, 수 kB)만 중계하고 영상은 지나가지 않는다. STUN/TURN 없이 같은 와이파이의 직접 주소로 연결한다. H.264를 먼저 고르고(폰 하드웨어 인코더), 가로 최대 1280px·최대 3Mbps·30장/초, 화질보다 장/초를 지킨다(`web/test/stage-view/rtc.js`).
  - 사람 윤곽은 **PC가 받은 영상에서 직접 계산**한다(`web/test/stage-view/pc-outline.js`, MediaPipe lite+분할, 깊이는 화면 폰과 같은 `view-person.js`, 판정 관절은 PC가 이미 받는 판정 폰 관절). 새 영상 장마다 같은 장을 화면에 그리고 MediaPipe에 넣으므로 윤곽과 영상이 항상 같은 장이다.
  - PC가 모두 WebRTC로 연결되면 화면 폰은 JPEG 전송과 자기 사람 인식을 멈춘다. 연결 안 된 PC가 하나라도 있거나 8초 안에 연결되지 않으면 JPEG로 보낸다(PC는 3~5초마다 다시 시도). PC는 WebRTC 영상이 1초 안에 들어오는 동안 V의 JPEG를 무시한다.
  - 화면 폰 성능 줄: `WebRTC 직접 · PC n/m대 · 장/초 · 해상도 · Mbps · 화질 낮춤 이유(폰 처리/와이파이)`. PC 오른쪽 `V 영상:` 줄: `WebRTC 직접 · 해상도 · 장/초 · 수신 대기 ms · 윤곽 PC 계산 ms` 또는 `JPEG 서버 중계 · WebRTC 상태`.
  - JPEG 방식(기존): 화면 폰이 JPEG를 서버로 보내고(가로 480~960, 기본 720), 이전 장이 폰을 떠나기 전이면 다음 장을 건너뛴다(밀린 장면을 쌓지 않음).

## 연결 규격 (`/ws/test/duo3d`)

- WebRTC 신호(2026-11-20): 서버 → PC 연결 직후 `rtc_hello{id}`. PC → 서버 `rtc_signal{to:'V',data}` → 화면 폰에 `rtc_signal{from:<PC id>,data}`. 화면 폰 → 서버 `rtc_signal{to:<PC id>,data}` → 그 PC에 `rtc_signal{from:'V',data}`. 상대가 없으면 보낸 쪽에 `rtc_signal_failed{to,reason:'not_connected'}`. `data.type`: offer/answer/ice/not_ready(카메라 전)/disabled(JPEG 선택)/bye(PC 떠남, 서버가 보냄). 판정 폰은 보낼 수 없다(`unsupported_message`).
- 판정 좌표 보정(2026-11-22): PC → 서버 `duo_auto_rotation{enabled}`(기본 true). `wide3d_status.view.auto_rotation`, `wide3d_status.cameras.<C0|C1>.correction{applied,x_m,y_m,yaw_deg,measured}`, 판정 폰 `multi3d_calib`의 `marker_offset_m:[x,y,0]`·`marker_yaw_deg`.
- 간격 자동 적용(2026-11-20): PC → 서버 `duo_auto_spacing{enabled}`(기본 true). 켜져 있으면 `wide3d_view_layout.spacing_m`이 현재 간격과 5mm 이상 다르고 0.5~3m이면 서버가 그 간격을 적용한다(PC의 간격 적용과 같은 처리). `wide3d_status.view.auto_spacing`에 상태가 들어간다.

- `role=phone&camera=C0|C1`: 넓은 무대와 같은 `mono3d_calib`(`marker_id`=번호)·`mono3d_frame`·`mono3d_jpeg`. `C2`는 거부(`bad_role_or_camera`).
- `role=phone&camera=V`: `wide3d_view_calib{image,K,camera{R,t,C}(무대 좌표),marker_ids:[0,1],spacing_m,marker_side_m,reprojection_max_px,fov_diag_deg,marker_poses?{"0"|"1":{center_m:[x,y],yaw_deg}}}`(marker_poses는 2026-11-22 추가, 없으면 간격만 옮김), `wide3d_view_layout{spacing_m,entered_spacing_m,yaw_deg:[ID0,ID1],relative_yaw_deg,reprojection_max_px,warn}`(실측 배치, PC 표시용, 2026-11-18), `mono3d_jpeg`만 받는다. 그 밖의 메시지는 `unsupported_message`. 판정 폰이 `wide3d_view_layout`을 보내면 `bad_message`. 서버 → PC `wide3d_status.view.layout`에 마지막 실측값이 들어가고, V가 끊기면 지운다(간격을 바꿔도 실측값은 유지).
- 서버 → 폰: `mono3d_status{camera,owner,layout:'duo',spacing_m,markers{0:x,1:x},view_calibrated}`. 화면 폰에만 판정 폰이 유효 프레임을 보낼 때 `duo_person{camera_id,joints(무대 좌표),source:'mono_approx'}`(최신 값만, 밀리면 버림).
- 화면 폰 → 서버 `mono3d_jpeg`에 `occlusion{encoding:'camera_z_mm_rg16_alpha_v1',width,height,data(PNG)}`·`occlusion_valid`·`occlusion_reason`을 붙이면 PC로 그대로 전달한다. PC 가림 텍스처는 최대 384×384.
- 서버 → PC: 넓은 무대 메시지 + `multi3d_calib{camera_id:'V',role:'view',...}`, `wide3d_status.view{connected,calibrated,reprojection_max_px,camera_height_m}`, `multi3d_model_state.model_test.stage.layout='duo'`.
