# 카메라 3대 3D 시험 페이지

2026-11-16 최신 후속: 3대는 사람 몸보정 순서를 생략하고 카메라별 마커 보정 후 바로 측정한다. 마커 K/R/t 보정은 삼각측량에 필요하므로 유지한다. 1대의 사람 가림은 발목 필수인 타격 좌표와 분리하고, 발목 미검출 시 보정된 몸통의 시각 전용 깊이를 사용할 수 있다. 이 좌표는 타격/서버 추적에 보내지 않는다. 폰에 윤곽/깊이/좌우 발목 상태를 표시한다. 실제 폰에서 보고된 가림 실패 원인을 확정한 것은 아니며 재시험이 필요하다.

2026-11-16 표시 확장: 마커 기준 중앙3D에 관측 관절 기반 머리/몸통/팔/다리 사람 표시를 추가한다. 1대/3대 PC 영상은 사람 윤곽 안에서 사람보다 뒤의 건물/파편/충돌선만 가린다. 3대는 최근3D 몸통 재투영이 현재JPEG/분할 프레임과 맞을 때만 깊이를 사용한다. 누락 관절 생성 없음, 오래된/무효 관측은 표시와 가림을 해제하며 실제 표면깊이·실폰 경계/부하는 별도다.

2026-11-16 최신 크기 변경: 사용자의 추가 축소/구역 동일 기준 요청으로 IT1 단독과 모든 소구역의 최고 건물 높이를 최초 보정 허리의70%로 맞춘다. 구역 전체의 폭·깊이·높이를 같은 비율로 바꿔 내부 건물 비율과 마커 중심 배치를 유지한다. 기존87개 평균0.95m 기반 개인배율 정책을 대체하며 구역별 최대높이 기준이다. 예: 허리1.02m이면 모든 구역/단독 최고높이0.714m. 이후 이동/복원/구역 왕복에도 같은 초기 허리 기준을 사용한다.

## 2026-11-16 마커 자동 인식

폰 카메라를 켜고 고정 단계에서 마커 검은 사각형의 실제 한 변과 바닥~렌즈 높이를 확인한 뒤 **마커 자동 인식**을 누른다. 기존 assets/markers/floor-direction-id0의 ArUco DICT_4X4_50 ID0 인쇄물을 사용한다. 입장용 QR이나 단순 흑백 사각형은 대상이 아니다. 흰 여백과 검은 테두리 전체가 영상 안에 보여야 한다.

검출은 최대720px 프레임에서 명암 분리→연결성분→볼록 외곽/사각형→검은 테두리와 ID0 비트·방향 검증을 수행한다. 같은 ID0가 여러 개면 거부한다. 6회 이상·900ms 이상 연속 안정 후 모서리를 확정하고 기존 화각/높이·자세 보정 품질검사를 적용한다. 초록 테두리와 보정 결과를 확인한 뒤 몸 보정으로 진행한다. 1대 자동 경로도 인쇄 마커 방향을 쓰고 저장된 모서리 방향을 보존한다. 검출·보정이 실패하면 거리/각도/반사/인쇄 크기를 확인하거나 **수동으로 모서리 찍기**를 쓴다.

자동은 모서리 선택을 대체하며 실제 마커 크기·카메라 높이 측정이나 렌즈 실측을 대체하지 않는다. 확정 후 검출을 중단하므로 마커/사람 움직임에 건물이 따라 움직이지 않는다. 카메라를 옮기면 마커와 몸 보정을 다시 한다. 합성 영상에서 1대/3대 경로와 회전/원근/잡음/오인식 거부를 검증했으며 실폰의 최대거리·역광/반사·추가부하는 미검증이다.



## 2026-11-16 현재 기준 — 최초 허리 고정

- 1대는 기존 마커 위 직립 몸 보정 완료 때 허리 기준을 한 번 만든다. 허리는 기존 키×0.6 추정(0.6~1.3m 제한)이며 실측 센서가 아니다. IT1 단독 높이를 이 값으로 정하고 바닥 마커 (0,0)에 고정한다. 이후 움직임/앉기/키 추정 변화/복원으로 자동 크기·위치를 바꾸지 않는다. 명시적으로 몸 보정을 다시 하면 새 기준을 만든다.
- 구역은 2개를 앞에, 가장 높은 1개를 뒤에 놓고 전체 바닥 외곽의 중심을 마커에 맞춘다. 2개 구역은 좌우 중앙 배치다. 기존 87개 평균높이0.95m로 정한 공통 축척에 최초 허리/0.95를 한 번 반영한다. 구역 전환은 동일 보정 비율을 사용하므로 같은 건물의 크기는 바뀌지 않는다. 모든 건물 높이가 각각 허리와 같다는 뜻은 아니다. 기존 고정0.95m/가로 일렬 배치 설명은 이전 정책이다.
- 3대 폰은 각자 마커 보정→몸 보정 화면으로 진행한다. 세 폰을 모두 연결한 뒤 한 폰 또는 PC 건물 시험의 '세 폰 몸 보정 시작'을 누른다. 마커 위 직립/양발접지, 코·어깨·골반·발목의 유효 3D와 세 시점, 최소20표본/2.5초 이상 연속 안정성을 확인해 허리를 저장한다. 완료 전에는 새 폰의 실제 손 타격을 중단한다. 재연결/카메라 재보정은 재몸보정을 요구하며 옛 크기를 실시간으로 추종시키지 않는다. 타임스탬프가 없는 구형 합성/재생 테스트 메시지는 호환 경로이며 실기기 완료 근거가 아니다.
- 폰 페이지는 건물과 충돌체를 그리지 않는다. 건물·충돌체·파편은 PC 화면에만 표시한다.
- 측정/몸보정 화면은 전체 원본 프레임을 contain으로 표시해 화면 잘림을 막는다. 전체 건물 외곽이 영상 여백6% 안에 들어오는지 검사하고 부족하면 거리/각도 변경·마커/몸 재보정 안내를 표시한다. 고정된 실제 크기를 유지하므로 가까운 카메라에서 임의로 세 건물을 모두 보장하거나 매 프레임 축소하지 않는다. 넓은 건물 구역은 상당한 촬영 거리가 필요할 수 있다.
- 배포는 npm run build:building-test 후 서버 재시작·폰/PC 새로고침. 실폰 허리/정합 정확도·시야 확보·장시간은 미검증이다.


`/test/multi3d/`는 `/test/mono3d/`와 **같은 흐름**(폰 고정 → 마커 모서리 → 보내기 → PC 화면)으로 폰 3대(C0·C1·C2)를 묶는 **시험용** 페이지다. 각 폰이 같은 바닥 마커로 자기 위치를 구하고, 서버가 2대 이상에서 보인 관절을 삼각측량해 **실제 3D**를 만든다. 몸 보정 단계는 없다. 기존 방·게임·`/ws/pose`·`/test/mono3d/`는 바꾸지 않았다. 결과는 `source: multi_view_test`로 표시하며 P3 완료 근거로 쓰지 않는다.

## 실행

IT1 실제 모델을 마커에 놓고 닿은 파편만 제거하는 별도 PC 화면은 `/test/building/`이다. 폰은 아래의 기존 3대 페이지를 그대로 쓴다. [파편 접촉 시험 실행·계약](BUILDING_FRAGMENT_TEST.md)을 따른다.

1. 서버를 재시작한다. 새 경로를 추가했다.
2. PC: `https://<PC 주소>:8443/test/multi3d/view.html?key=<접속키>`
3. 폰 3대: `https://<PC 주소>:8443/test/multi3d/?key=<접속키>`. 첫 화면에서 각각 **C0, C1, C2**를 고른다(`&camera=C1`로 지정해도 된다).
   1. 폰을 고정하고 그 폰의 높이를 넣는다.
   2. 마커 모서리 4개를 아무 순서로 누른다.
   3. 결과의 빨강(+X)·초록(+Y) 축이 세 폰 모두 실제 마커의 같은 방향을 가리키는지 확인한다.
   4. **보내기**를 누르고 시계 교환이 끝날 때까지 잠깐 기다린다. 서버와 세 폰/PC를 함께 새로고침해야 새 시각 정렬을 사용한다.
4. 폰끼리 사람이 설 자리 기준 **60~120°** 벌려 둔다(예: 앞, 앞-왼쪽, 왼쪽 옆). **서로 마주보게(약 180°) 두면** 두 광선이 거의 한 줄이 되어 그 방향 거리를 잴 수 없다. 서버가 바닥면 기준 150° 초과·25° 미만인 쌍을 경고한다.
5. 마커 자리가 건물이다. 사람은 **마커 위가 아니라 옆**에 서서 휘두른다. 발(없으면 엉덩이)이 건물 바닥 면적 + 10cm 안에 있으면 느린 동작은 타격을 세지 않고 경고하지만, 손/발을 1.5m/s 이상 빠르게 움직이면 겹쳐 있어도 파편이 깨진다(건물 판정 시험 기준). 사람이 서 있으면 서버가 코 높이로 키를 추정해 건물 높이를 허리(키 × 0.6)로 맞춘다.

## 계산 방식

2026-11-11: 공용 마커 보정에서 작은/납작한 마커·큰 재투영 오차·모서리 ±1px(720px 기준) 변화에 수직 방향이 15° 넘게 흔들리는 보정을 거부한다. 키/무늬 인식 성공만으로 바닥 방향을 확정하지 않는다. 실패 시 폰을 가까이/위로 옮겨 마커를 크게 촬영하고 다시 보정한다. 수치와 실측 한계는 [단일 시험 보정 품질](MONO3D_TEST.md)을 따른다.

- **마커 방향:** 세 폰이 같은 축을 써야 하므로 "화면에서 먼 변 = 앞" 규칙(mono3d)을 쓰지 않는다. 모서리 안쪽 4×4 무늬를 읽어 ArUco DICT_4X4_50 ID0의 실제 위쪽(+Y)을 찾는다(`web/test/multi3d/aruco.js`). 무늬를 못 읽으면 보정하지 않는다. ID0의 네 회전은 서로 10칸 이상 달라 1칸 오독까지 허용한다.
- **카메라 자세/렌즈:** 폰 화면은 기존 화각 근사 K·호모그래피·자세 정밀화와 높이로 화각 역산을 유지한다. 서버는 선택적 `dist`(4/5/8/12/14계수)를 받아 픽셀을 왜곡 제거한 좌표로 바꾼다. 현재 폰 화면이 실제 렌즈 보정값을 자동 측정하거나 불러오는 기능은 없다. `dist` 미제공은0이며 실제 K/dist·기준점 실측은 후속이다.
- **좌우 맞추기:** 뒷모습을 보는 폰의 좌우 이름을 비교한다. 충분히 분리돼 보이는 어깨/골반을 우선 사용해 빠른 손목 잡음이 사람 전체의 좌우를 뒤집는 영향을 줄였다. 몸통 정보가 없으면 기존 전체 관절 비교로 돌아간다. 결과에 `swapped_left_right`를 표시한다.
- **삼각측량:** 3대 시험 전용 `backend/tracking/test_fusion.py`를 사용한다. 기존 공통 `/ws/pose` 추적 경로는 바꾸지 않았다.
  - 관절13개, visibility0.5 이상을 쓰고 검출 신뢰도4승으로 가중한다. 가중 DLT 후 Huber 가중 픽셀 재투영 최소화로 좌표를 정밀화한다.
  - 3대가 품질을 만족하면 함께 사용한다. 실패하면2대 후보를 평가하며 카메라 앞쪽·재투영·광선교차 조건을 검사한다. 상충하는 후보를 분간하기 어려우면 `ambiguous_views`로 보류한다.
  - 재투영 한도는 영상 짧은변720px 기준8px이며 해상도에 비례한다. 광선의 예각 교차각이5° 미만이면 `poor_geometry`로 거부한다. 반대 방향으로 거의 같은 직선인 시점도 거부한다.
  - 사람 모양으로 좌표를 강제하거나 누락 관절을 생성하지 않는다. 화면에서 관절이 빠지면 사용 시점/제외 이유를 먼저 확인한다.
- **시각 맞추기:** 새 폰은 같은 추론 입력 캔버스의 시각을 보낸다. 서버의 nonce가 붙은 ping/pong과 기존 DeviceClock으로 폰별 `performance.now()`를 서버 시각에 맞춘다. 최소3개 표본·최근20개중 최소RTT를 사용하고 RTT절반이10ms를 넘으면 시점을 보류한다. 매핑은 대칭 지연 가정이므로 실제 노출시각 동기화를 보장하지 않는다.
  - 카메라별 최대60프레임 버퍼에서 느린 최신시점(최신보다100ms 넘게 뒤처진 카메라 제외)을 기준으로 최근접 입력을 선택한다. 기준과30ms 이내이고 전체 시각차+양끝 시계 불확실성 합이40ms 이내인 조합만 쓴다. 중복/역순 입력·400ms이상 지난 입력·미래 입력은 제외한다.
  - 새 입력시각과 구형 도착시각을 섞지 않는다. 구형폰만 연결된 경우 도착시각40ms 호환 경로를 `server_arrival`로 명시한다. 새 경로는 `inference_input_aligned`이며 **카메라 하드웨어 노출 시각이 아닌 추론 입력 시각**이다. 한 프레임 내 노출/읽기·렌더 지연은 남는다. 결과는 최대40회/초다.
- **건물·타격:** mono3d와 같은 규칙이다(마커 자리, 폭·깊이 0.3m, 허리 높이, 여유 0.05m, 안에 들어오거나 직전→현재 선분이 지나가면 1회). 서버가 판정해 모든 화면이 같은 횟수를 본다. 같은 손목은 0.3초 안에 다시 세지 않는다. 시각이 조금씩 다른 화면을 합친 결과가 들락날락해서 한 번 휘두른 것이 두 번 세지는 것을 막기 위해서다. PC 화면에서 크기·위치·높이(자동/직접)를 바꾸고 횟수를 0으로 돌릴 수 있다.

## PC 화면

- **왼쪽:** 세 폰의 영상(약 4장/초)과 2D 뼈대를 보여 준다. 3D 결과를 각 카메라에 다시 그린 원도 함께 그린다. 원이 손목에 붙으면 세 화면의 보정이 서로 맞는다는 뜻이다.
- **가운데:** 마우스로 돌려 보는 3D 화면이다. 폰 3대의 위치와 방향, 손목을 본 카메라에서 손목까지의 선, 건물, 몸 관절, 손목 궤적을 그린다. 타격 시 건물이 흔들리며 빨개지고 파편이 튄다.
- **오른쪽:** 타격 수, 손목 좌표·사용 카메라/재투영 오차/교차각, 유효관절 수, 시각 정렬 방식·제외 카메라/이유, 추정 키·건물 설정을 보여 준다. 중앙 흰 골격은 측정된 유효 관절만 연결한다.

타격음은 기본 활성 상태다. PC는 화면을 한 번 클릭하고, 폰은 카메라 시작·보정 조작으로 브라우저 오디오를 활성화한다. 서버가 보낸 새 유효 3D 타격에서 폰·PC가 충격·붕괴·잔해음을 재생하며, PC의 **소리 끄기/켜기**로 즉시 음소거할 수 있다. 초기 접속·재접속의 누적 점수, 중복·무효 결과와 음소거 중 타격은 나중에 다시 재생하지 않는다. 보정 안내용 삐 소리는 유지한다. 음소거해도 타격 판정·점수·시각 효과는 그대로 동작한다.

같은 새 유효 타격에서 폰 AR 영상·PC 카메라 영상과 3D 보기에 충격광·충격파·회전 잔해·먼지·건물 반동을 투영한다. 초기·중복·무효 결과에는 효과를 다시 만들지 않으며 음소거 중에도 애니메이션은 유지한다. 효과는 1.4초 수명·최대 3회·72개 입자로 제한하고 리셋/재접속 시 비운다. 입자 궤적과 반동은 렌더 프레임 수 대신 경과 시간을 사용한다. 서버의 삼각측량·타격·점수·실제 건물 손상 규칙은 바꾸지 않는다.

`npm run test:ar`는 정적 서버에서 합성 입력으로 두 모드의 폰·PC 4개 경로를 검증한다. 현장 3대 입력·정합·실제 서버 구동·소리 청취·성능 측정과는 별도다. 명령·통과 수·미검증 범위는 [검증 요약](asset-validation/ar-feedback/summary.json)을 따른다.

## 연결 규격 (`/ws/test/multi3d`)

- `role=phone&camera=C0|C1|C2`: 번호마다 폰 하나만 받는다. 새 폰이 연결되면 이전 폰을 끊는다.
  - 폰이 보내는 것:
    - `multi3d_calib`: `image`, `K{fx,fy,cx,cy}`, `R`(행 우선9개), `t`, `C`, `marker_side_m`, 선택적`dist`. 바뀔 때만 보내며 기존 버퍼/궤적을 재기준한다.
    - `multi3d_frame`: `landmarks` 정규화한 `[x,y,visibility]`33개 또는null, `clock_id`, `input_at_ms`, `timestamp_source:inference_input`. 새 추론 입력만 약30회/초 전송한다.
    - `multi3d_clock_pong{nonce,clock_id,device_time_ms}`: 서버의 `multi3d_clock_ping{nonce,server_send_ms}`에 답한다. 연결별 발급된 nonce만 인정한다.
    - `multi3d_jpeg`: 폭 360px.
  - 서버는 회전행렬·크기·형식을 검사하고, 512KB를 넘으면 거부한다.
- `role=viewer`: `multi3d_config{building}`, `multi3d_reset_hits`를 보낼 수 있다. 늦게 들어와도 마지막 보정·영상·결과를 받는다.
- 서버가 보내는 것:
  - `multi3d_fused`: `joints{name:{p,cams,err_px,ray_angle_deg,excluded_cameras}|null}`, `reasons`, `cameras_used`, `spread_ms`, `timing`, `input_reference_ms`, 카메라단위`excluded_cameras`, `building/hits/hit/cameras`. 시계준비/불확실성은`cameras`에도 포함한다. 폰/PC 모두에 보내며 타격 결과는 신뢰큐, 나머지는 최신값만 전송한다.
  - `multi3d_status`
- 접속 키로 보호한다. 저장은 하지 않는다.

## 2026-11-16 사람 3D 표시·사람 앞 가림

마커 기준 3D 화면은 관측한 코·어깨·팔꿈치·손목·골반·무릎·발목을 사용해 머리·몸통·팔다리를 그린다. 실제 사람 스캔/사진 텍스처가 아닌 관절 기반 사람 모형이다. 없는 관절은 만들지 않고 해당 부위를 숨긴다. 입력 만료(500ms)·연결 종료·보정 변경 시 남은 모형을 정리한다. 건물의 초기허리70% 고정·물리/점수는 그대로다.

PC 영상의 사람 뒤 가림은 기본 ON이다. MediaPipe 사람분할 윤곽과 관절의 카메라Z 깊이를 결합한 깊이 전처리로 뒤쪽 모델만 가리며 앞쪽 모델·윤곽 밖은 보존한다. PC는 동적 파편도 가린다. 깊이는 같은 JPEG에 깊이PNG로 동봉한다.

3대 폰도 기존 Pose의 분할 출력을 켜며 추가 추론 모델은 쓰지 않는다. 최근 융합 결과가 200ms 이내이고 네 몸통 관절이 필수로 있고 보이는 관절들이 현재 랜드마크와 재투영 오차 max(12px,영상대각2.5%) 안에서 맞을 때만 그 깊이를 사용한다. 서버가 교정한 좌우 라벨 반전도 반영한다. 늦거나 불일치하면 가림을 보류한다. PC에서 카메라 프레임이 순차 도착해 잠깐 1시점만 정렬됐을 때는 200ms 이내 최근 유효 몸통을 유지하고, 유효 2시점 이상에서 추적 무효가 확인되면 즉시 해제한다. 실제 관절 누락은 복원하지 않는다.

사람 표면 깊이는 관절 깊이에서6cm를 보정한 근사이고 실제 깊이 센서가 아니다. 실폰의 가림 경계/빠른 동작/조명/지연·세 폰 추가 부하는 미검증이다. 적용은 build:building-test 후 서버 재시작·PC/폰 새로고침이며, 3대 폰은 분할 출력 옵션을 새로 적용하도록 카메라를 다시 켠다.

## 2026-11-16 실사용 후속: 3대 몸보정 생략·가림 진단·발목 범위

3대 폰은 카메라→마커→보내기 순서로 진행한다. 신규 사람 몸보정 화면으로 자동 이동하지 않고 PC의 몸보정 시작 버튼도 숨긴다. 서버는 구형 폰의 requires_body_calibration=true 요청도 필수 단계로 강제하지 않는다. 기존 선택된 고정 건물 크기를 사용한다. 카메라별 실제 마커 보정/저장값 재사용은 필요하며 없는 K/R/t를 자동 생성하지 않는다. 이전의 필수 3대 몸보정 설명은 이력이다.

1대 가림은 타격용 result.valid에만 묶지 않는다. 발목이 안 보여 feet_required_for_depth가 된 경우, 이미 몸 보정이 있고 어깨/골반과 worldLandmarks가 유효하면 발 관측을 제외한 torso_scale 추정으로 가림용 깊이를 계산한다. visual_torso_only/collision_usable=false로 구분하고 타격 좌표·서버 추적·점수에는 사용하지 않는다. JPEG의 occlusion_valid/occlusion_reason으로 PC에도 시각 가림의 독립 유효성을 전달한다. PC는 깊이 패킷 500ms 만료·잘못된 PNG·연결/보정 변경을 정리한다.

폰의 새 상태 문구는 윤곽 부재/읽기 실패, 깊이 부족, 가림 준비 픽셀 수, 시각용 몸통 추정 여부, 좌우 발목 검출 여부를 알려 준다. 모델 번들/폰 스크립트 캐시버전을 올렸다. 서버 재시작과 폰/PC 새로고침, 폰 카메라 재시작 후 확인한다. 이 수정은 코드에서 발견한 가림 중단 조건을 보완한 것이며 사용자의 실제 폰 실패 원인을 재현/확정한 것은 아니다.

발목은 1대/3대 입력·3D 사람 표시·1대 깊이 기준에 포함된다. 3D 건물 FragmentTest.update의 실제 타격 관절은 여전히 양 손목이다. 별도 phone_2d 게임은 앞서 발차기 경로를 연결했다. 발목 추적과 3D 발차기 타격 완료는 구분한다.
