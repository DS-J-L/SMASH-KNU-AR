# IT1 분석 파편 QA 체크포인트

기본 게임 패키지를 교체하지 않는 별도 실험용 후보다. 상태는 `EXPERIMENTAL_NOT_GAMEPLAY_ACCEPTED`이며 실제 게임·폰·AR·장시간 안정성의 승인을 뜻하지 않는다. 캠퍼스 v71 정적 모델과는 별도 파일·런타임이다.

## 실행 범위

최신 main `db6ea7a41328124df0b5e8d6284a1d31fa291a51`의 별도 작업 사본에 통합했다. 저장된 카탈로그 기본 `knu-it1-v3`, 기존 캠퍼스 v13 경로, 서버의 허용 건물과 방별 폰 입력 계약은 보존한다. `qa_compound=1`일 때만 메모리의 선택 목록에 후보를 추가한다.

- [파편 검토 화면](../web/monitor/fracture/index.html): 서버에서 `/monitor/fracture/?qa_compound=1&building=knu-it1-analytic-164-v1`
- [단일 PC 검토 화면](../web/monitor/single/index.html): 서버에서 `/monitor/single/?qa_compound=1&building=knu-it1-analytic-164-v1`
- `/monitor/phone-game/`에서는 이 후보를 명시 선택하면 `analytic_qa_not_supported_for_phone_input` 오류로 모델 생성 전에 중단한다. 현재 서버가 허용한 기본 폰 게임은 그대로다.
- `qa_frame`은 `original`, `display_translated`, `local_rotated90Y`, `display_translated_local_rotated90Y`만 허용한다. 그 외 값은 오류다.

`display_translated`는 표시 원점만 [1,2,3]으로 옮기고 세계 바닥은 그대로 둔다. 건물과 바닥을 함께 옮긴 별도 오프라인 물리 시험과 같지 않다.

## 통합과 보존

동결 인계는 설치 앱 HEAD `7b0990a356d962e2c00c85524f3da86883a6a78e` 기준5수정·17추가였다. 현재 main에서 single/main.js가 바뀌었으므로 파일 전체 교체 대신7개 패치 구간을 3방향 대조했다. 기존 폰 입력·RoomInputLink·방별 서버 점수/시각·타격/소리·수동 중지를 보존했다. 관련 없는 추적 파일 변화가 없음을 병합 직후 해시로 확인했다.

독립 검토에서 찾은 보완:
1. 서버가 아직 허용하지 않은 분석 후보를 폰 게임에 보내지 않도록 생성 전 차단.
2. 단일 PC 분석 화면에도 ‘미승인 QA 후보’ 상태와 실험용 한계를 표시.
3. 연구 폴더에 의존하던 파편 테스트를 저장소 안의 패키지와 고정 해시·독립 변환 계산으로 재현하도록 분리. 외부 연구 비교 결과를 최신 main 시험으로 간주하지 않는다.

원본 인계 ZIP SHA256: `df8322146e20c8ccf8bfb945814f16576570c86ce558bac84d9b52ee2857f992`. ZIP 원본과 설치 앱, 기존 캠퍼스·복원 백업은 보존한다. 참고 사진·개인 설정·인증 자료·실험 원시 덤프는 게시하지 않는다.

## 검증 기록과 남은 일

이 문서와 함께 최종 통합 검증 요약을 기록한다. 정적 계약/모의 액터 시험, 실제 브라우저에서의 합성·키보드 입력, 오프라인 native 물리를 구분한다. 기본 패키지 승격이나 전체 게임 완료로 해석하지 않는다.

실제 폰·MediaPipe 입력·AR 정합·소리 청취·장시간·성능·연속 충돌 보장·실측 형상은 별도 미검증이다. 기존 브라우저 시험의 오래된 기대값 및 간헐 합성 입력 실패도 숨기지 않고 결과에 함께 기록한다.

출처·이용 조건은 [캠퍼스 v71](CAMPUS_V71_CHECKPOINT.md)의 원본 에셋 계보와 [에셋 파이프라인](ASSET_PIPELINE.md)을 따른다. 새 schema는 기존 schema1 패키지의 호환 계약을 대체하지 않는다.
