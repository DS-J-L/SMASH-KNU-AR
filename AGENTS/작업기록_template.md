# 작업 기록 양식

양식을 해당 개인/PM 진행 파일의 누적 기록 아래에 복사한다. `<...>`는 실제 내용으로 바꾼다. 시작 기록을 먼저 남기고, 종료할 때 같은 작업의 결과를 채운다. 종료 후 정정은 새 기록으로 추가한다.

## 1. 개인 또는 공통 작업

```markdown
### <YYYY-MM-DD HH:mm KST> — <작업명>

- 담당 / 기록자: <이름 또는 Codex>
- 작업 구분: <개인 개발 / 공통 관리 / 문서 / 검증>
- Phase: <P0~P6 또는 공통 관리 — 개발 Phase 통과와 별개>
- 상태: <진행 중 / 검토 요청 / 통합 확인 / 완료 / 막힘>
- 읽은 계획·기록: <파일명, Phase/절 제목, 마지막 기록>
- 연결할 계획 항목: <체크리스트 원문 또는 해당 항목의 위치>
- 이번 목표·완료 기준: <무엇을 확인하면 이 작업이 끝나는가>
- 검증 계획: <실행·실기기·문서 확인 방법>

진행·종료 결과:

- 바꾼 파일·결과물: <실제 파일, PR·커밋 또는 로컬 결과물>
- 어디까지 완료: <실제로 충족한 기준>
- 검증 방법·조건·실제 결과: <실행 명령 또는 확인 절차 / 통과·실패·미실행>
- 입력·장비 범위: <live / synthetic / replay / keyboard_demo / 해당 없음>
- 남은 일·미검증: <구체적인 범위>
- 막힌 점·도움·해제 조건: <없음 또는 원인 / 담당 / 필요한 결과>
- 다음 한 단계·재개 위치: <열 파일, 실행 명령, 필요한 장비 등>
- 인계 대상·넘긴 자료: <이름과 파일/계약 또는 해당 없음>
- 갱신한 계획 체크리스트·현황: <실제 변경한 항목 또는 변경 없음과 이유>
- 종료·중단 시각: <YYYY-MM-DD HH:mm KST 또는 진행 중>
```

검증 범위가 다르면 작업을 나눠 기록한다. 예를 들어 단일 폰 등록 성공은 완료로 남길 수 있지만, 3대 동시 수신 항목은 미검증으로 유지한다.

## 2. 공통 Phase 통합 확인 — PM 기록용

```markdown
### <YYYY-MM-DD HH:mm KST> — <P번호> 통합 확인

- 확인자 / 기록자:
- 대상 버전·기기·모델·설정·보정:
- 읽은 완료 기준: PM_plan.md의 <P번호·절>
- 개인 결과물·근거: <각 progress 기록 및 결과물>
- 시나리오 / 기대 결과 / 실제 결과:
- 실제·합성·재생·키보드 구분:
- 미통과·미검증 항목:
- 공통 Phase 판정: <통합 확인 / 완료 / 막힘>
- 후속 담당·할 일·재확인 목표일:
- 다음 Phase에 넘길 결과:
- 갱신한 진행현황 행:
```

## 3. 현재 상태 요약 — 파일 상단 갱신용

```markdown
| 항목 | 현재 값 |
| --- | --- |
| 마지막 갱신 | <YYYY-MM-DD HH:mm KST> |
| 현재 Phase·작업 상태 | <P번호 / 상태, 또는 공통 관리> |
| 마지막 완료한 것 | <검증된 결과와 누적 기록 위치> |
| 현재 작업 | <이번 작업 하나> |
| 남은 일·미검증 | <진행 범위와 차이> |
| 다음 한 단계 | <즉시 시작할 구체적 행동> |
| 막힌 점·인계 | <담당·자료·해제 조건> |
```
